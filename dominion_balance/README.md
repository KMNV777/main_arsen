# Анализ файла `dominion_grants.json`

## О чём этот файл

Файл `dominion_grants.json` — это **конфигурация имплантов / модулей игрока** для игрового режима «Dominion» (судя по структуре — мод/плагин на базе Source-движка, скорее всего CS2/CS:GO, на это указывают `damage_mask`, `aim_punch_scale`, `Geiger.BeepHigh`, `Player.Wade`, `Buttons.snd15`).

### Структура

```jsonc
{
  "<SteamID64 игрока>": [
    {
      "factory": "<id фабрики импланта>",
      "buff":   { "name": "<id эффекта>", ...параметры },
      "debuff": { "name": "<id эффекта>", ...параметры }
    },
    ...
  ]
}
```

Корневой ключ `"76561198836236005"` — это **SteamID64** конкретного игрока. Внутри лежит массив записей, в которых каждому **импланту** (`factory`) сопоставлены **активный бафф** (положительный эффект) и **компенсирующий дебафф** (отрицательный эффект). Это классическая схема «risk/reward»: за каждое преимущество игрок платит каким-то ограничением.

### Что встречается в исходных грантax (16 штук)

| Фабрика (имплант) | Бафф (что даёт) | Дебафф (чем платит) |
|---|---|---|
| `accuracy_zone_v1` | +15% скорости при HP < 20 | +10% штраф к перезарядке |
| `anti_kinetic_v1` | +10% урона телу при плёнке бомбы | +15% уязвимость к HE-гранатам (`mask=64`) |
| `bio_patch_hp_v1` | +20 брони при движении с ножом | +15% уязвимость к огню (`mask=8`) |
| `bio_regeneration` | Активный «зеркало пуль» 64f / cd 2560f | -5% скорости с ножом |
| `chrome_armor` | +50 HP, +50 max HP, абилка `armor_pulse` (+100 брони) | -15% скорости |
| `chrome_repair_v2` | Сброс кулдауна абилки (3200f) | Блок стрельбы 2f, скорость 0 |
| `chromo_armor_tank` | Абилка тушения (cd 1280f) | Запрет прыжка после урона 32f |
| `credit_reader_v1` | +30 max HP при смерти союзника | +10% к aim-punch |
| `cyber_limb_accuracy` | x2 скорость подъёма по лестнице | Звук «вброд по воде» при ходьбе |

### Единицы и условности

* `velocity_modifier` — множитель скорости (`1.0` = база).
* `damage_scale` — множитель урона (`>1.0` — больше, `<1.0` — меньше).
* `*_frames` — длительность в тиках сервера (для CS2 это 64 tick → 64f ≈ 1 секунда).
* `damage_mask` — битовая маска типа урона (`8` = огонь, `64` = взрывная волна).
* `body_only` / `leg_only` — фильтры зон попадания.
* `apply_for_attacker` / `apply_for_victim` — кому применяется модификатор.
* `max_health_delta`, `immediate_health_delta`, `armor_bonus` — целочисленные дельты.
* `cooldown_frames` / `active_frames` / `lock_frames` — продолжительность активной фазы и кулдауна.

## Балансные варианты

В папке лежат **три** документа с пересчитанными значениями. Все варианты сохраняют **тот же набор фабрик и имена эффектов**, но крутят коэффициенты под разную философию баланса.

| Файл | Философия | Окно бафф/дебафф | Кому подходит |
|---|---|---|---|
| `variant_1_aggressive.json` | High-risk / High-reward | Жирные баффы, болезненные дебаффы | Соло-фрагерам, агрессивному стилю, pub-серверам |
| `variant_2_defensive.json` | Low-risk / Low-reward | Скромные баффы, мягкие дебаффы | Командной игре, медленным раундам, новичкам |
| `variant_3_competitive.json` | Tuned / симметричный | Усреднённые значения, минимизированные «мусорные» дебаффы | Соревновательному режиму, киберспорту |

### Принципы баланса (общие)

1. **Симметрия дельт.** Если бафф даёт `+X%` атакующего параметра, дебафф снимает не более `+X·k%` в близкой по влиянию плоскости (`k≈1.0` — паритет, `k>1` — наказание, `k<1` — поощрение).
2. **Тип цены.** Боевой бафф → боевой дебафф; утилитарный бафф → утилитарный дебафф. Нельзя «комфорт за смерть» и наоборот, иначе один из вариантов абуз. Это правило соблюдается во всех трёх файлах через подбор величин.
3. **Каппинг параметров.** `velocity_modifier ∈ [0.70, 1.30]`, `damage_scale ∈ [0.70, 1.30]`, `max_health_delta ∈ [-25, +75]` — чтобы не выходить за пределы движка/комфорта.
4. **Фрейм-тайминги.** Все `*_frames` кратны 32 (полтика секунды на 64 tick), чтобы лочить/анлочить эффекты на дискретных интервалах.
5. **Косметика остаётся косметикой.** Где исходный дебафф — это звук или мерцание (`mini_radar_v1`, `cyber_limb_accuracy`, `fast_network_v2`), мы его не утяжеляем — иначе нарушится принцип «цена соответствует выгоде».

Численные сводки см. в начале каждого варианта в поле `_meta`.
