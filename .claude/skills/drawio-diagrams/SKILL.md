# Диаграммы draw.io в репозитории

## Подход
Диаграммы **генерируются скриптами**, а не рисуются вручную: раскладка детерминирована, правки видны в git-диффе, данные (шаги, роли, сервисы) лежат в одном месте.

Два генератора:
- `scripts/drawio_kit.py` — лёгкий кит без зависимостей: `Page` → `Cell`/`Edge` → `.drawio` (несколько страниц, несжатый XML) + SVG-превью из той же модели. Эталонный пример — `scripts/build_release_process.py` (процесс релиза, 4 страницы).
- `drawpyo` (`requirements.txt`) — используется в C4-генераторах `scripts/build_*_c4_component.py`.

## Правила для схем процессов
1. **Дорожка = зона ответственности (ЗО)**; у каждого шага — ID, название, роль. Один шаг = одна подзадача в Jira.
2. **Параллельность видна явно**: fork/join-планки (чёрная вертикальная полоса), общая пунктирная зона «параллельный блок», шлюз AND-join с условиями.
3. **Возвраты** — красные пунктирные стрелки с подписью причины; зависимости — серые пунктирные; привязка к git — точечные.
4. **Сервис — часть процесса**: заголовок каждой страницы содержит `%service%`, `%direction%`, `%version%` (свойства `<object>`; меняются в draw.io через *Edit Data*), отдельная матрица «сервис × этап».
5. Новое/уточнённое относительно прежней схемы помечай (оранжевая рамка + «★нов.»), опциональное — пунктирной рамкой.
6. Связи крепи к фигурам (`source/target` + `exitX/entryX`) — стрелки не «отваливаются» при ручной правке.
7. Раскладка: шаг ≈ 150×62, шаг по X ≈ 190, дорожки — горизонтальные полосы; вертикальные связи между дорожками проверяй на пересечение с узлами.

## Рабочий цикл
```bash
pip install -r requirements.txt            # drawpyo, matplotlib (кит drawio_kit.py без зависимостей)
python3 scripts/build_release_process.py   # .drawio + SVG + docs/release-process.md
python3 -c "import xml.dom.minidom as m; m.parse('docs/drawio/10-release-process.drawio')"   # XML well-formed
```
Проверка раскладки глазами (в облаке нет draw.io Desktop): SVG → PNG через Chromium:
```bash
/opt/pw-browsers/chromium-*/chrome-linux/chrome --headless --no-sandbox --disable-gpu --hide-scrollbars \
  --screenshot=out.png --window-size=W,H file://$PWD/docs/svg/10-release-process-1.svg
```
Широкие страницы режь по кускам (PIL `crop`) и смотри по частям.

## Формат `.drawio`
`<mxfile><diagram name><mxGraphModel><root>` → `mxCell` (`vertex="1"` / `edge="1"`). Подписи — HTML (`html=1`), значение экранируется как XML-атрибут. Подпись ребра задаётся `value`, позиция вдоль ребра — `mxGeometry x ∈ [-1, 1]`.

## Чего избегать
- Не рисовать вручную XML для больших схем; не сжимать диаграмму (теряется дифф).
- Не вписывать в схему ФИО/названия, в которых не уверен, — выноси в таблицу «подтвердить».
- Не публиковать схему как Artifact без просьбы пользователя.
