# ОМГ ИТ‑архитектура — реестр «серых зон» и запросов к заказчику

Документ раскрывает по каждой выявленной проблемной области схемы «ОМГ ИТ архитектура (верхнеуровн.)» пять требуемых столбцов:

1. **Текущий результат обследования** — что наблюдаем сейчас (AS‑IS) по схеме и сопутствующему контексту.
2. **Описание «серой зоны» / Проблематика** — что именно не подтверждено/не закрыто и чем это критично.
3. **Риск (вероятность / влияние)** — качественная оценка и последствия при материализации.
4. **Комментарии и допущения** — ограничения текущего анализа, сделанные предположения.
5. **Запросы к раскрытию** — какие документы, данные и интервью нужны для закрытия «серой зоны».

Оценка риска: вероятность (Н / С / В) × влияние (Н / С / В). В/В — критический, В/С — высокий, С/С — средний, иначе — низкий.

> Реестр является рабочим: после получения ответов заказчика формулировки должны быть уточнены, а риски — переоценены.

## 1. Фрагментированные SCADA без единого диспетчерского окна

| Поле | Содержание |
|---|---|
| Текущий результат обследования | На промыслах ОМГ эксплуатируются независимые SCADA/DCS: SIMATIC HMI SCADA WinCC, SEDMAX, DeltaV, СДМО «Мирол» / WellPilot (GPRS‑сервер, Телескоп+4). Каждая система обслуживает свой участок (мех. добыча, энергетика, подготовка нефти, бурение). Указан Siemens WINCC OA как «единая база данных реального времени», статус — жёлтый (планируется замена/развитие). |
| Описание «серой зоны» / Проблематика | Отсутствует единый контур реального времени и сквозная картина производственного процесса. Разнородные SCADA не интегрированы между собой, общий слой операционных данных (Operations Data Layer / Real‑Time Data Infrastructure) не подтверждён. В рамках текущего анализа не подтверждены наличие/стадия проекта по созданию единой диспетчерской и консолидации SCADA в WINCC OA. Полноценные архитектурные схемы и планы консолидации не предоставлены. |
| Риск (вероятность / влияние) | В / В — при аварии оператор переключается между интерфейсами, теряется время на локализацию; рост MTTR, риск нарушения режимов, ухудшение показателей OEE и увеличение потерь добычи; невозможность построения корректной производственной аналитики и ЦУМ. |
| Комментарии и допущения | Ограничения анализа связаны с отсутствием полноценных архитектурных схем и сетевых диаграмм ОТ‑сегмента. Предполагается, что WINCC OA выбран как целевая платформа, но проектные документы не видели. |
| Запросы к раскрытию | Архитектура ОТ‑уровня по Purdue (L0–L3), перечень SCADA/DCS/ПЛК с версиями и вендорами, матрица интеграций (OPC UA / OPC DA / Modbus / IEC‑104), карта сетей АСУТП, план консолидации в WINCC OA, SLA реального времени, резервирование, журналы инцидентов. Уточнить бизнес‑процессы, ИТ‑решения, АСУ ТП (уровни, SCADA, ПЛК), схемы интеграций, первичные источники (узлы доступа, датчики, счётчики, контроллеры), потоки данных «поле — офис», «серые зоны» в сборе и передаче телеметрии — для последующего консалтинга по АСУТП. |
