# Руководство для авторов базы знаний

## Золотые правила

### Пишите как пользователь, а не как разработчик

| ❌ Плохо | ✅ Хорошо |
|---|---|
| "Ошибка аутентификации OAuth 2.0" | "Не могу войти через Google" |
| "Недостаточно привилегий" | "Вы не можете этого сделать" |
| "Транзакция отклонена эмитентом" | "Платёж не прошёл" |
| "Синхронизация прогресса недоступна" | "Прогресс не сохранился" |

### Одна проблема — одна статья

Не пишите "Проблемы со входом" на 10 подпроблем.
Пишите отдельные статьи:
- "Забыл пароль"
- "Не приходит письмо для сброса пароля"
- "Аккаунт заблокирован"
- "Не могу войти после смены пароля"

Пользователь ищет конкретно. Длинная статья отпугивает.

### Решение — в начале, объяснение — в конце

Пользователь хочет починить проблему, а не понять её архитектуру.

```
✅ Правильная структура:
1. Что делать (шаги)
2. Почему это помогает (опционально, кратко)
3. Если не помогло — эскалация

❌ Неправильная структура:
1. Введение что такое авторизация
2. Технические детали
3. ...много текста...
4. Наконец, что делать
```

---

## Как писать шаги

**Используйте повелительное наклонение:**
- "Нажмите", "Перейдите", "Введите", "Выберите"

**Один шаг = одно действие:**
- ❌ "Откройте настройки и перейдите в безопасность и нажмите изменить пароль"
- ✅ Шаг 1. Откройте **Настройки**  
  Шаг 2. Перейдите в раздел **Безопасность**  
  Шаг 3. Нажмите **Изменить пароль**

**Выделяйте элементы интерфейса жирным:**
- "Нажмите кнопку **Войти**"
- "Перейдите в **Профиль → Настройки → Безопасность**"

## Скриншоты

- Делайте скриншоты актуальной версии клиента
- Выделяйте стрелкой или рамкой нужный элемент
- Подпись обязательна
- Формат: PNG, ширина 800–1200px
- Хранение: `/assets/screenshots/<category>/<article-slug>/`

---

## Теги

Теги нужны для поиска. Добавляйте:
1. Ключевые слова по-русски (как пишет пользователь)
2. Ключевые слова по-английски
3. Синонимы и опечатки частые

```yaml
# Пример для статьи о входе через Google
tags: [
  google, войти, вход, авторизация, login,
  "не могу войти", oauth, "через гугл"
]
```

---

## Поле `auto_resolve`

`auto_resolve: true` — бот может закрыть тикет, показав эту статью, без передачи агенту.

Ставьте `true` только если:
- Решение не требует действий со стороны поддержки
- Проблема не связана с потерей денег или доступа к аккаунту
- Статья имеет рейтинг полезности > 75%

---

## Поле `severity`

| Значение | Когда использовать |
|---|---|
| `high` | Пользователь не может войти / потерял деньги / не может играть |
| `medium` | Функция работает, но неправильно / неудобно |
| `low` | Вопрос "как сделать X" / косметические проблемы |

---

## Блок эскалации

Обязателен в каждой статье. Не менять шаблонный текст — он A/B-тестируется.

Единственное, что можно менять — список того, что нужно указать при обращении
(зависит от категории проблемы).

---

## Процесс публикации

```
1. Создать файл по шаблону в нужной категории
2. Заполнить frontmatter
3. Написать контент
4. Пройти чеклист в шаблоне
5. Pull request → ревью саппорт-лида
6. После merge — статья появляется в KB через ~5 минут
```
