## Принципы написания статей

### 1. Структура каждой статьи
Каждая статья следует единому шаблону (см. `_templates/article-template.md`):
- **Симптом** — как пользователь описывает проблему своими словами
- **Причина** — краткое объяснение (не всегда нужно)
- **Решение** — пошаговые инструкции, пронумерованные
- **Если не помогло** — эскалация в чат/тикет с заполненным контекстом

### 2. Правило одной статьи — одна проблема
Не объединять "не могу войти" и "забыл пароль" в одну статью.
Лучше две короткие, чем одна длинная.

### 3. Заголовки — это симптомы, а не термины
- ✅ "Игра вылетает при запуске на Windows"
- ❌ "Ошибка инициализации DirectX Runtime"

### 4. Теги и метаданные
Каждая статья содержит frontmatter с тегами для поиска:
```yaml
---
title: "Не могу войти в аккаунт"
tags: [login, authorization, access, войти, аккаунт]
category: account
severity: high        # high | medium | low
auto_resolve: false   # true = бот может закрыть без агента
last_updated: 2026-05-27
---
```

### 5. Оценка полезности
Каждая статья имеет кнопку "Помогло / Не помогло".
Статьи с рейтингом < 60% за 30 дней попадают в очередь на переработку.

## Категории и приоритеты

| Категория | Типичный SLA | Auto-resolve % | Приоритет |
|---|---|---|---|
| Аккаунт (взлом, блокировка) | 2 ч | 30% | Критический |
| Оплата (списание без покупки) | 4 ч | 20% | Высокий |
| Технические (вылеты, не запускается) | 8 ч | 60% | Средний |
| Геймплей (прогресс, предметы) | 24 ч | 70% | Средний |
| Социальные функции | 48 ч | 80% | Низкий |
| Правила и апелляции | 72 ч | 10% | Низкий |

## Жизненный цикл статьи

```
Идея → Черновик → Ревью (QA + саппорт-лид) → Публикация → Мониторинг → Архив
```

- **Идея**: из тикетов (топ-10 повторяющихся запросов в неделю)
- **Черновик**: автор пишет по шаблону, прикладывает скриншоты
- **Ревью**: проверка точности решения и читаемости
- **Публикация**: статья доступна в поиске и боте
- **Мониторинг**: ежемесячный аудит рейтинга полезности
- **Архив**: статья устарела (фича удалена/изменена) — убирается из поиска, сохраняется в архиве

## Интеграция с чат-ботом

Бот использует базу знаний через полнотекстовый поиск по тегам и заголовкам.
Логика обработки запроса:

```
Сообщение пользователя
        │
        ▼
 Поиск по KB (теги + полнотекст)
        │
   ┌────┴────┐
   │         │
Найдено   Не найдено
   │         │
Показать  Уточняющий вопрос
 статью   (категория?)
   │         │
   └────┬────┘
        │
  Помогло?
  ├── Да → закрыть тикет
  └── Нет → создать тикет с контекстом + передать агенту
```

При эскалации к агенту передаётся:
- ID пользователя
- Что пользователь написал
- Какие статьи были показаны (и не помогли)
- Автоматически собранный контекст (ОС, версия клиента, последние действия)

## Метрики здоровья базы знаний

| Метрика | Цель | Как считать |
|---|---|---|
| Self-service rate | > 60% | тикеты закрытые без агента / все тикеты |
| Article helpfulness | > 75% | "Помогло" / все оценки статьи |
| Search success rate | > 70% | поиски с кликом на статью / все поиски |
| Coverage | > 80% | тикеты с KB-статьёй / топ-50 проблем |
| Staleness | < 5% | статьи не обновлявшиеся > 90 дней |
