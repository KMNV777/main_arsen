# ОТЧЁТ по результатам исследования ИТ-ландшафта АО «Эмбамунайгаз»

**Объекты обследования:**
- НГДУ «Кайнармунайгаз» — месторождение В. Молдабек (ответственный: В. Молдабек)
- НГДУ «Жылыоймунайгаз» — месторождение С. Нуржанова (ответственный: С. Нуржанова)

---

## 1. Цель обследования

Проведение анализа текущего состояния информационно-технологического ландшафта АО «Эмбамунайгаз» в части производственных и корпоративных информационных систем, инфраструктуры АСУ ТП, систем телемеханики, SCADA-систем, каналов передачи данных и интеграций с верхнеуровневыми системами группы КМГ.

Основными задачами обследования являются:

- определение текущей архитектуры ИТ-ландшафта (производственный и корпоративный контуры);
- анализ применяемых программно-технических средств автоматизации и управления;
- оценка состояния каналов передачи данных и интеграционных связей;
- анализ интеграции с корпоративными информационными системами КМГ;
- выявление потенциальных рисков и узких мест;
- формирование рекомендаций по модернизации и повышению отказоустойчивости.

## 3. Описание архитектуры ИТ-ландшафта

### 3.1 Корпоративный контур (общий для ЭМГ)

Большая часть корпоративных информационных систем размещена в облаке; в собственном ЦОД сосредоточены производственные системы, которые технически не могут быть вынесены в облако.

#### 3.3.1 Центральная система управления ЦППН

Система построена по распределённой архитектуре; единый центральный ПЛК отсутствует. Управление реализовано через несколько шкафов АСУ ТП:

| Подсистема | ПЛК | Функциональная зона |
|-----------|-----|-------------------|
| Резервуарный парк (РВС) | Siemens SIMATIC S7-1500 | Контроль уровней, объёмов, состояния резервуаров |
| НГС, газоанализаторы | Siemens SIMATIC S7-300 | Контроль сепарации, давления, уровня, газовой среды |
| УПС (1–7) | Siemens SIMATIC S7-300 | Контроль уровней нефти и воды, клапанов, давления и температуры |
| ГС, ОГ | Siemens SIMATIC S7-300 | Контроль газосепарации, отстойников и подготовки воды |
| Печи ПТБ-10-64 | Siemens SIMATIC S7-300 | Локальные САУ печей |

SCADA-система — Siemens WinCC v7.5; данные со всех контроллеров поступают в единую систему.

#### 3.3.2 Особенности архитектуры и выявленные ограничения

- Уровнемеры ПМП-201 (УПС) опрашиваются напрямую SCADA-системой по OPC DA через OPC Server «Sens OPC» — часть данных поступает в обход контроллерного уровня; при отказе OPC-сервера канал получения данных теряется.
- Газовые расходомеры (4 счётчика) работают по Modbus RTU; двухчасовые показатели формируются программно на уровне SCADA — риск потери расчётных данных при остановке SCADA.
- Использование двух поколений ПЛК Siemens (S7-300 и S7-1500) создаёт неоднородность аппаратной платформы. S7-300 относится к устаревшей линейке — актуален вопрос жизненного цикла и доступности запасных частей.

#### 3.3.3 ТМ нефтепровода (С. Нуржанова)

Система телемеханики нефтепровода протяжённостью ~56 км:

| Узел | ПЛК | Назначение |
|------|-----|-----------|
| ПКУ №1 | Siemens SIMATIC S7-1200 | Узел запуска поршня |
| ПКУ №2 | Siemens SIMATIC S7-300 | Линейный пункт контроля |
| ПКУ №3 | Siemens SIMATIC S7-300 | Линейный ПК / приёмный узел |

Связь между ПКУ — по оптоволокну (последовательная топология). КУУН интегрирован через KepServerEX (OPC DA) с контроллером Delta-V. БДР передаёт данные через Wi-Fi радиомост Ubiquiti NanoStation M2 по S7Comm. Данные ТМ нефтепровода во внешние системы **не передаются**.

#### 3.3.4 АСУ ТП насосных агрегатов (С. Нуржанова)

Платформа: Honeywell (SCADA + ПЛК). Система является локальной и **не интегрирована** с внешними информационными системами. Использование платформы Honeywell наряду с Siemens формирует разнородную технологическую среду.

#### 3.3.5 АСУ ТП УППВ ВРП (С. Нуржанова)

| Объект | ПЛК | Канал данных |
|--------|-----|-------------|
| Модульные установки ВРП | Siemens SIMATIC S7-1200 | Wi-Fi радиомост Ubiquiti NanoStation M2, аналоговый 4–20 мА |
| Площадной объект УППВ | Siemens SIMATIC S7-400 | SCADA WinCC v7.5 |

Интеграция через TIA Portal v16. Данные УППВ во внешние системы **не передаются**.

#### 3.3.6 АСУ ТП УБС «Прорва» (С. Нуржанова)

ПЛК Siemens SIMATIC S7-1200; SCADA WinCC v7.5. Уровнемеры ПМП-201 передают данные через OPC DA + Wi-Fi радиомост. Газовые счётчики — по HART. Данные УБС во внешние системы **не передаются**.

### 3.4 Система телемеханики скважин (ТМ ИСУ) — В. Молдабек и С. Нуржанова

На скважинах обоих месторождений применяются интеллектуальные станции управления **ИСУ VLT SALT** (Danfoss) — системы частотного регулирования с функциями автоматического управления, защиты оборудования и передачи данных.

Архитектура сбора данных:

| Источник | Протокол | Получатель |
|---------|---------|-----------|
| ИСУ VLT SALT | Modbus RTU | MCO-101 |
| MCO-101 | HTTP | Сервер СДМО |
| Сервер СДМО | ODBC | ИС «Интеллектуальное месторождение» |

Предусмотрены два варианта передачи данных в СДМО:

1. **LoRaWAN** — ИСУ → MCO-101 → LoRa-устройство → базовая станция LoRaWAN → POST TCP/IP → сервер СДМО;
2. **Wi-Fi** — ИСУ → MCO-101 → роутер → Ubiquiti NanoStation → сервер СДМО.

Идентификация скважин: по LoRaWAN — по ID абонентского оборудования; по Wi-Fi — по IP-адресу роутера (разные принципы идентификации требуют актуального справочника).

| Показатель | В. Молдабек | С. Нуржанова |
|-----------|------------|--------------|
| Всего скважин | 360 | 148 |
| Оснащены ИСУ | 331 (91,9%) | 125 (84,5%) |
| Без ИСУ | 29 | 23 |
| С датчиками давления | 20 (5,6%) | **0** |

## 4. Схема интеграции и обмена данными

### 4.1 Сводная схема потоков данных

```
[Уровень L1 — Промышленный контур]
  SCADA WinCC v7.5 (СП «В. Молдабек», ЦППН «Прорва», АГЗУ, УППВ, УБС)
  ИСУ VLT SALT (скважины) → MCO-101 → СДМО
  АГЗУ (ПЛК) → Wi-Fi → Сервер ТМ АГЗУ

[Уровень L2 — Шлюзы и протоколы]
  OPC UA (основной протокол передачи в ИМ)
  OPC DA / KepServerEX (ИСУН, КУУН, устаревшие системы)
  Modbus TCP/RTU (КУУН, АГЗУ, газовые расходомеры)
  S7Comm (печи, ПКУ)
  ODBC (СДМО, ABAI → ИМ)
  Wi-Fi / LoRaWAN (ИСУ скважин → СДМО; АГЗУ → ТМ АГЗУ)

[Уровень L3 — Интеграционный слой ИМ]
  ИС «Интеллектуальное месторождение» (10.32.10.99)
  Python ETL (cron + Django/Celery)
  → Аналитика ЭМГ (:8099)
  → ABAI (PostgreSQL read: 08:00, 13:30, 18:00)

[Уровень L4 — Корпоративные сервисы]
  ИС ABAI (abai.kmg.kz) — производственная ИС
  SAP ERP — финансово-кадровый хаб
  Directum — документооборот
  SMAX — ITSM
```

### 4.2 Детализация потоков ИС «Интеллектуальное месторождение» (ИМ)

| Источник | Протокол / формат | Данные | Частота |

## 5. Анализ текущего состояния

### 5.1 Сильные стороны

**Производственный контур:**
- Высокий уровень оснащения скважин ИСУ: 91,9% (В. Молдабек) и 84,5% (С. Нуржанова) от фонда;
- Применение Siemens WinCC v7.5 как основной SCADA-платформы на большинстве объектов;
- Широкое использование промышленного оборудования Siemens (S7-1200, S7-1500);
- Использование OPC UA для передачи данных в систему учёта и ИМ;
- Наличие интеграции ЦППН «Прорва» с системой учёта и ИС «Интеллектуальное месторождение»;
- Наличие межсетевого экрана между технологическим (ТСПД) и корпоративным (КСПД) контурами АГЗУ;
- Наличие телемеханики удалённых объектов (ТМ нефтепровода по ВОЛС);
- Двойной вариант передачи данных с ИСУ (LoRaWAN + Wi-Fi) обеспечивает резервный канал;
- Предпосылки для предиктивной диагностики насосного оборудования (параметры ЧРП, токи и температуры двигателей).

**Корпоративный контур:**
- Внедрена гибридная облачная модель (ЦОД + Qazcloud IaaS) — снижены инфраструктурные риски для корпоративных ИС;
- Мониторинг событий ИБ 24×7 обеспечивается ОЦИБ Qazcloud с формализованным SLA;
- Процессы реагирования на инциденты ИБ формализованы внутренними НПА;
- SAP ERP является устойчивым хабом финансовых и кадровых интеграций;
- Directum (САПФИР) обеспечивает корпоративный документооборот в рамках группы КМГ;
- Argus Pro внедрён в промышленную эксплуатацию с 2025 г., заменив устаревший CityPoint;
- SMAX функционирует как единая ITSM-платформа КМГ с 2023 г.

### 5.2 Выявленные ограничения и риски

#### 5.2.1 Производственный контур — архитектурные ограничения

| Ограничение | Описание |
|------------|---------|
| Неинтегрированные подсистемы | Данные ТМ нефтепровода, АСУ ТП насосных агрегатов, УППВ ВРП и УБС не передаются во внешние ИС; данные БДР (СП «В. Молдабек») не интегрированы в общую SCADA |
| Разнородность платформ | ЦППН «Прорва»: Siemens S7-300 + S7-400 + S7-1200 + S7-1500 + Honeywell — несколько поколений и вендоров |
| Устаревшее оборудование | S7-300 и S7-400 — устаревшие линейки с ограниченной доступностью модулей; риск невозможности замены при отказе |
| Прямой опрос SCADA | Уровнемеры ПМП-201 (ЦППН, УБС) и отдельные приборы опрашиваются напрямую SCADA в обход ПЛК — снижение единообразия и резервируемости |
| Расчёты на уровне SCADA | Двухчасовые показатели газа рассчитываются в WinCC — при остановке SCADA данные теряются |
| Последовательная топология ТМ | Нефтепровод (ПКУ №1–3): повреждение участка ВОЛС приводит к потере связи с несколькими узлами |
| Беспроводные каналы | Wi-Fi (Ubiquiti NanoStation M2/M5) — ключевой канал для АГЗУ, ИСУ, ВРП, УБС — без описанного резервирования |
| Аппаратная неоднородность АГЗУ | 6 типов АГЗУ / 4 контроллерные платформы — разные карты Modbus, SCADA-шаблоны, компетенции |
| Датчики давления | 20 из 360 скважин В. Молдабек (5,6%) и 0 из 148 скважин С. Нуржанова оснащены датчиками давления |
| Отсутствие единого кустового интерфейса | Данные ИСУ, АГЗУ и ВРП разнесены по разным SCADA/ТМ-системам без единого интерфейса куста |

#### 5.2.2 Корпоративный контур — ключевые проблемы

| Риск | Описание |
|-----|---------|
| Данные и аналитика | Единая корпоративная модель данных ЭМГ не сформирована; MDM / Data Governance / Data Office как функция отсутствуют; ответственность за данные «размазана» по бизнес-подразделениям; единого владельца НСИ нет |
| КХД | Корпоративное хранилище данных на уровне ЭМГ не создаётся осознанно — ожидается «сверху» от КМГ, что ставит аналитику и сквозную отчётность ЭМГ в зависимость от темпа и архитектурных решений материнской структуры |
| ABAI | Реализовано только 6 отчётных форм из 58; 52 в доработке; ключевые расчётные / аналитические модули используются как вспомогательные; ЭМГ не управляет очередью развития напрямую — ABAI разрабатывается внешним подрядчиком (КМГ Инжиниринг) |
| Интеграции | Отсутствует централизованная интеграционная платформа (ESB / API Gateway); обмен между ИС реализован «точка-точка»; реестр потоков, SLA на интеграционные обмены и карта «источник–приёмник–протокол–частота» отсутствуют |
| Аналитика — силосы | Аналитика живёт во встроенных средствах SAP, 1С, ABAI, Directum — без единой версии правды; расхождения между системами не закрываются регулярными процессами |
| Облако и инфраструктура | ИС размещены в Qazcloud (IaaS, VMware) без публично описанных DR/BCP, RPO/RTO и политики резервного копирования; сегментация OT/IT между производственным ЦОД и облаком не формализована |
| ИТ-управляемость | Реестр ИС с владельцами, критичностью и SLA только готовится; архитектурный комитет, ADR, корпоративные стандарты не подтверждены |
| Параллельные кадровые контуры | SAP HCM и 1С 8.2 «Зарплата» используются параллельно без явного источника истины — риск расхождений по ФОТ и налоговой отчётности |
| Актуальность as-is картины | Схема не отражает изменений: SMAX внедрён с 2023 г. (обозначен как отсутствующий), ТБД выведена в архив (Q4 2024), CityPoint заменён ArgusPro (2024–2025) |
| Вендорный и санкционный риск | Зависимость от SAP, Directum, VMware, западных АСУ ТП |

## 6. Рекомендации по модернизации

### 6.1 Производственный контур — архитектурные рекомендации

1. **Единый интеграционный уровень:** централизовать сбор технологических данных; внедрить единый OPC UA сервер или промышленный шлюз данных для всех подсистем (ЦППН, насосные агрегаты, УППВ ВРП, УБС, ТМ нефтепровода).
2. **Устранить прямой опрос SCADA:** постепенно перевести критически важные прямые опросы приборов (ПМП-201) с уровня SCADA на уровень ПЛК или промышленного шлюза.
3. **Перенести расчёты с SCADA:** рассмотреть дублирование расчётов двухчасовых показателей газа на уровне контроллера или отдельного сервера учёта.
4. **Интегрировать изолированные подсистемы:**
   - ТМ нефтепровода — поэтапно подключить к верхнеуровневым системам через OPC UA с контролируемым перечнем передаваемых параметров;
   - АСУ ТП насосных агрегатов (Honeywell) — определить минимальный набор параметров для передачи в систему учёта;
   - УППВ ВРП и УБС — обеспечить передачу ключевых параметров в аналитическую систему;
   - БДР (СП «В. Молдабек») — интегрировать в общую SCADA.
5. **Оценить жизненный цикл:** подготовить план поэтапной миграции с S7-300 и S7-400 (с учётом доступности запасных частей и поддержки).
6. **Реализовать резервирование SCADA:** резервирование серверов SCADA и серверов архивов.
7. **Единая модель тегов:** унифицировать правила наименования параметров, единицы измерения и признаки достоверности данных по всем подсистемам.

### 6.2 Сетевые рекомендации

1. **Резервирование каналов связи:** обеспечить резервный канал для критичных объектов (БГ СП «В. Молдабек», ВРП, УБС, АГЗУ с высоким вкладом в добычу).
2. **Унификация каналов ИСУ:** перевести на единый стандарт — LoRaWAN как основной канал (отказаться от двойной идентификации скважин).
3. **Кольцевая топология ТМ нефтепровода:** рассмотреть резервируемую или кольцевую топологию вместо последовательной.
4. **Мониторинг сетевого оборудования:** внедрить централизованный мониторинг радиомостов, коммутаторов, серверов и контроллеров (задержки, потери пакетов, уровень сигнала, доступность узлов).
5. **Резервное питание:** предусмотреть резервное питание сетевого оборудования на удалённых объектах.

### 6.3 Рекомендации по данным и интеграциям (корпоративный контур)

1. **Расширение инструментального контроля скважин:** установить датчики трубного и затрубного давления, приоритизировав скважины с высоким дебитом, нестабильным режимом и частыми остановами. Целевой ориентир — не менее 30–40% фонда обоих месторождений.
2. **Единый кустовой интерфейс:** разработать концепцию единой кустовой телемеханики с объединением данных ИСУ, АГЗУ и ВРП в одном интерфейсе (переход от куста к скважине, АГЗУ или ВРП).
3. **Унификация модели данных АГЗУ:** унифицировать наименования тегов, единицы измерения, признаки качества, временные метки и правила архивирования; вести централизованный реестр карт Modbus TCP.
4. **Единый справочник ИСУ:** сформировать реестр соответствия скважина ↔ ИСУ ↔ MCO-101 ↔ LoRa ID ↔ IP-адрес роутера ↔ канал передачи данных.
5. **ESB / API Gateway:** инициировать проработку централизованной интеграционной платформы (DataFlow, WSO2, SAP PO, 1С:Шина или иное) для перехода от «точка-точка» к управляемым потокам с SLA, реестром и мониторингом.
6. **MDM / Data Governance:** инициировать создание функции Data Office или MDM-комитета; определить домены НСИ и их владельцев (материалы, контрагенты, оборудование, скважины, объекты).
7. **Реестр ИС:** завершить формирование реестра с атрибутами: бизнес-владелец, ИТ-владелец, критичность, SLA, тип поддержки, локация размещения.
8. **DR / BCP:** разработать или актуализировать планы восстановления (DR), определить RPO/RTO для каждой критичной ИС.
9. **Сегментация OT/IT:** формализовать разделение ответственности между ЭМГ, Qazcloud (IaaS), ОЦИБ и КМГ Инжиниринг по модели Shared Responsibility; описать сегментацию сред между производственным ЦОД и облаком.

## 7. Заключение

В результате обследования установлено, что ИТ-ландшафт АО «Эмбамунайгаз» по месторождениям В. Молдабек и С. Нуржанова обеспечивает выполнение основных функций технологического управления, диспетчерского контроля и корпоративного учёта.

**Производственный контур** характеризуется высоким уровнем оснащения скважин ИСУ (>84% по обоим месторождениям), наличием действующих SCADA-систем на ключевых объектах и интеграцией с ИС «Интеллектуальное месторождение». Вместе с тем инфраструктура сформирована из нескольких самостоятельных подсистем с неоднородными платформами автоматизации и различными схемами интеграции. Ключевые ограничения: отсутствие единого интеграционного слоя для всех подсистем, низкая оснащённость скважин датчиками давления (особенно критично для С. Нуржанова — 0%), беспроводные каналы без резервирования, изолированность ряда систем от верхнеуровневых ИС.

**Корпоративный контур** демонстрирует зрелую базовую инфраструктуру (SAP ERP, Directum, гибридное облако, внешний SOC), однако имеет системные пробелы: отсутствие единой корпоративной модели данных и MDM, «точка-точка» интеграции без ESB, функциональная незавершённость ABAI (6 из 58 форм в продуктиве), зависимость аналитической и производственной повестки от темпа КМГ Инжиниринг и корпоративного центра КМГ.

Реализация предложенных мероприятий позволит:

- повысить отказоустойчивость производственной инфраструктуры;
- централизовать контроль по всем подсистемам месторождений;
- повысить качество цифровой модели месторождения за счёт расширения датчиков давления и единой кустовой телемеханики;
- снизить эксплуатационные риски за счёт унификации платформ и устранения прямого опроса SCADA;
- создать основу для формирования единой версии правды по добыче, фонду скважин и производственным KPI;
- обеспечить условия для дальнейшей цифровизации в рамках программы «Цифровое месторождение».
