## 1. Текущие результаты анализа

- **Что сделано**
  - Обследован ИТ-ландшафт ЭМГ (НГДУ «Жылыоймунайгаз», «Кайнармунайгаз») в части АСУТП и корпоративного контура; собран реестр 19 ИС с протоколами, частотой и направлением обмена
  - Подтверждена **гибридная модель размещения**: собственный ЦОД + IaaS на платформе ТОО «Qazcloud» (VMware) — корпоративные ИС в облаке, производственные системы (АСУТП) в ЦОД
  - Зафиксировано ядро данных группы КМГ — **ИС ABAI** (с IV квартала 2024 г.); ТБД выведена из эксплуатации в архив; ABAI сопровождается ТОО «КМГ Инжиниринг» по сервисной модели
  - Описана архитектура «Интеллектуального месторождения» (хост 10.32.10.99): OPC DA/UA, Modbus TCP, MySQL/PostgreSQL, REST в аналитику ЭМГ (:8099), packet_service, Speech, SMTP
  - Построены сводные схемы (C4, Mermaid, SVG, draw.io): сводная архитектура, корпоративный ландшафт, фокус ЭМГ–ABAI, ИМ, SAP-хаб, слои ABAI, общий ИТ-ландшафт

- **С кем провели интервьюирование**
  - С. Нуржанова, СП В. Молдабек (АСУТП НГДУ «Жылыоймунайгаз», «Кайнармунайгаз»)
  - Владельцы ИС ABAI и контура «Интеллектуальное месторождение» (ЭМГ + КМГ Инжиниринг)
  - Подразделения КЦ КМГ по корпоративным сервисам (SAP ERP, АСУНСИ, КХД, Active Directory, SAS-FM, Procu)
  - Профильные ИБ-специалисты (ОЦИБ ТОО «Qazcloud», мониторинг 24×7)

- **Поездки на месторождения и офисы**
  - НГДУ «Жылыоймунайгаз», НГДУ «Кайнармунайгаз» — площадки АСУТП и ТМ
  - Узлы КУУН, АГЗУ, реклоузеры КОА; НПС-3 (Modbus TCP); площадки SDMO (4 региона Danfoss)
  - Офисы КЦ КМГ и ЭМГ — согласование матрицы «КЦ–ЭМГ–КМГИ»

- **Полученные результаты (первичные материалы согласованы)**
  - Подтверждён состав корпоративного контура: SAP ERP + 1С (учёт), Directum (СЭД), SMAX (ITSM с 2023 г., централизованная для КМГ платформа), ArgusPro (GPS-мониторинг с 2025 г., заменил CityPoint)
  - Подтверждена формализация процессов ИБ: внутренние НПА (Инструкция по действиям пользователей, Правила управления инцидентами ИБ), мониторинг событий 24×7 ОЦИБ Qazcloud с фиксированным SLA
  - Согласовано: реестр ИС с владельцами / критичностью / SLA — **в стадии подготовки**; часть материалов передана только в бумажном виде

## 2. Выявленная проблематика

- **Децентрализованная архитектура сбора данных**
  - Корпоративная **ESB / API Gateway не внедрена** — обмен между ИС реализован «точка-точка» по бизнес-потребностям, без целевой модели и без реестра потоков
  - Единственный явно описанный внешний обмен — **связка с КМГ Инжиниринг через SQL Server → ИСУН**; карта «источник–приёмник–протокол–частота» отсутствует
  - 9+ разрозненных источников телеметрии (PostgreSQL ABAI, Kepware OPC DA, OPC UA АСУТП/ТМ, Modbus КУУН, 4× MySQL SDMO, MySQL KTM, koa-cm WinCC HDA, PostgreSQL emg) подключены напрямую к ИМ
  - Параллельно работают **3 контура производственных данных**: ИС ABAI, ИМ/cmv2 (10.32.10.99), АСДЦ (iis.thkmg.kz) — без чёткой мастер-роли
  - Верхнеуровневая as-is схема расходится с фактом (SMAX внедрён, но обозначен как отсутствующий; ТБД выведена в архив; CityPoint заменён на ArgusPro) — доверие к схеме как основанию решений снижено

- **Высокая степень ручного ввода и дублирования данных**
  - Корпоративная **модель данных в ЭМГ не сформирована**; **MDM / Data Governance / Data Office как функция отсутствует**, ответственность за данные «размазана» между бизнес-подразделениями
  - **Единого владельца НСИ нет**; справочники ведутся локально (1С, Excel, главный инженер, маркшейдеры, фрагменты SAP MDM) — расхождения по материалам, контрагентам, оборудованию, скважинам
  - Аналитика и отчётность строятся **во встроенных средствах SAP, 1С, ABAI, Directum** — «силосы» без единой версии правды
  - SAP ERP обменивается с 12+ системами по CSV/XLSX/MT940/RFC; реестры СИЗ, добычи и нарушений рассылаются XLSX-файлами по SMTP — фактически Excel-документооборот
  - **Дубли в верхнеуровневой схеме**: несколько City Point, два контура EAM, две KPI, дублирование SAP MDM, несколько SCADA, параллельные кадровые контуры **SAP HCM vs 1С 8.2 «Зарплата»** без явного источника истины

- **Отсутствие единой базы данных по осложнениям**
  - ABAI как централизованная платформа функционально **не достроена**: в продуктиве **только 6 отчётных форм из 58**, ещё **52 формы в доработке**; ключевые расчётные / аналитические модули используются как вспомогательные
  - На ОМГ **«красные» / «жёлтые» статусы**: «Мониторинг осложнений», «Подбор ГНО», «Анализ эффективности ГТМ/ТКРС», «Управление заводнением», «ИМ», «Интегрированное моделирование», «Цифровое месторождение», «Экомониторинг», «ИС УТО» — текущая практика в цифровом виде ЭМГ не подтверждена
  - **Корпоративное КХД на уровне ЭМГ отсутствует** — внедрение планируется «сверху», на уровне КЦ КМГ; до его готовности — длительное «бумажно-Excel» состояние по производственному планированию и аналитике
  - ABAI разрабатывается и сопровождается **внешним подрядчиком (КМГ Инжиниринг)** — ЭМГ не управляет очередью развития напрямую, развитие функционала и КХД в зоне ответственности КЦ / КМГ Инжиниринг
  - Расхождения между SAP, 1С, ABAI, Directum, SCADA и лабораторными хранилищами **не закрываются регулярными процессами** → разные версии правды по добыче, фонду скважин, материалам, контрагентам, кадрам → блокирует программу «Цифровое месторождение»
  - **Ключевые риски**: интеграционный (рост стоимости каждого нового внедрения и техдолга), облачный (DR/BCP, RPO/RTO, сегментация OT/IT не подтверждены), регуляторный (нет автоматизированного экомониторинга и планирования добычи/ГТМ при росте требований Самрук-Қазыны), вендорный/санкционный (SAP, Directum, VMware, западные АСУ ТП)

## 3. Текущие рекомендации

- **Формирование единой платформы-источника данных, исключение ручного дублирования Excel**
  - Свести 3 контура (ABAI / ИМ / АСДЦ) к одной модели данных по скважинам, режимам и ремонтам с единым мастером и зафиксированным RACI «ЭМГ ↔ КМГ Инжиниринг»
  - Закрыть **52 отчётные формы ABAI** и зафиксировать дорожную карту функциональных модулей (анализ ГТМ, подбор ГНО, заводнение, мониторинг осложнений) с критериями приёмки и стадиями (идея/ТЭО/ТЗ/пилот/проект)
  - Заменить пакетные CSV/XLSX-выгрузки SAP ↔ 1С / FC / Кадры / СИЗ на потоковые API через SAP PO / сервисную шину; SMTP-рассылки реестров перевести на дашборды поверх единого хранилища
  - Унифицировать ТБД ABAI: единый стек хранения (PostgreSQL), вывести параллельные Oracle/MsSQL из дублирующих ролей; завершить **реестр ИС с атрибутами** (бизнес-/ИТ-владелец, критичность, SLA, тип поддержки, локация)

- **Выстраивание целевой архитектуры единой платформы (Data Lake / сервисная шина), определение первоочередных потоков для автоматизации**
  - Развернуть **корпоративный Data Lake** поверх КХД АО НК КМГ как единый приёмник данных ABAI / ИМ / SAP / SCADA с привязкой к ЭМГ; подключить SCADA/DCS-данные в аналитический слой (вопрос остался открытым)
  - Внедрить **ESB / API Gateway / iPaaS** (варианты: SAP PO, WSO2, Apache Kafka, Camel, DataFlow, 1С:Шина) вместо точечных SOAP/REST/CSV; назначить ответственного за реестр интеграций; зафиксировать SLA на потоки
  - Приоритетные потоки для автоматизации: **(1)** учёт добычи нефти и газа (скважина/куст/ДНС/месторождение), **(2)** ГТМ и эффективность ТКРС, **(3)** осложнения и подбор ГНО, **(4)** ТОиР оборудования (единая EAM-платформа: IBM Maximo / SAP EAM / 1С:ТОИР), **(5)** НСИ и закупки
  - Закрыть **«красные» гэпы** целевой архитектурой: производственное планирование, ЦУМ, моделирование скважины/пласта/нефтесбора, петрофизика, экомониторинг, DLP, **внутренний портал сотрудника** (SharePoint / Bitrix / Confluence) с интеграцией в Directum
  - Усилить инфраструктуру и ИБ: **DR-площадка**, RPO/RTO, политика резервного копирования, **сегментация OT/IT**, расширение ИБ-стека (SIEM, IAM/PAM, NGFW, EDR/XDR, MFA, VM, защита АСУТП); зафиксировать **Shared Responsibility** ЭМГ ↔ Qazcloud ↔ ОЦИБ ↔ КМГ Инжиниринг
  - Внедрить **архитектурное управление**: архкомитет, ADR, корпоративные стандарты и принципы, роль архитектора, KPI и обязательные интеграции в соответствии с требованиями КМГ и Самрук-Қазыны; матрица as-is → to-be с приоритезацией по вкладу в добычу, рискам и стоимости

- **Унификация НСИ: мастер-система на базе АСУ НСИ, единые справочники скважин, оборудования, материалов**
  - АСУНСИ КМГ + **Informatica MDM Product 360** — мастер для ДЗО (ЭМГ, ОМГ, КМГИ), а не только для КЦ; план перехода ЭМГ к единой MDM
  - Единые домены НСИ: **скважины** (с привязкой к КГИС / ArcGIS), **оборудование** (паспортизация через единую EAM), **материалы** (через Procu / ИСЭЗ Самрук-Қазына), **контрагенты** (Compliance Control, «Система управления контрагентами» — уточнить: CRM / MDM-контрагентов / compliance), **объекты** (АГЗУ, ГУ, ЦППН, БКНС, КУУГ, УПСВ, СИКН)
  - Привязать Procu, SAP, ABAI, ИМ, ИСУТО, ИСОТ к единым кодам НСИ; назначить **владельцев мастер-данных по доменам** и SLA на изменения
  - Закрыть кадровый контур: определить **источник истины** между SAP HCM и 1С 8.2 «Зарплата», устранить расхождения по ФОТ и налоговой/статистической отчётности
  - Провести отдельную рабочую встречу с профильными специалистами ЭМГ (как предложено): инвентаризация доменов НСИ, оценка качества данных, согласование плана MDM-внедрения
