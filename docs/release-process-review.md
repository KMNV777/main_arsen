# Расхождения документов и как они устранены

Сверены: эталонный процесс (Confluence), Релизная политика ЕАРМ, ДК выпуска релизов, «Доступы для релизов», «Менеджмент команд разработки», карточки ролевой модели. Все расхождения учтены в итоговой схеме — [`release-process.md`](release-process.md).

| Расхождение | Как устранено в итоговой схеме | Документ |
|---|---|---|
| Политика, эталон и ДК описывали разные процессы (ПМТ/ПСИ, ПТЗ, PreProd, уведомление). | Единая последовательность из 32 шагов. ПСИ ИБ — шаг релиз-борда: если не нужен, релиз-инженер сразу пропускает, если нужен — загружает документ. Отдельный шаг ПТЗ в схему не включён. | Эталон, Политика |
| Не было правила ведения веток; релизы пересекаются по времени. | Ветки вынесены на отдельную схему: ветка создаётся на старте спринта от master, допускается несколько веток параллельно, фича-фриз в конце спринта; что не успели — в следующий релиз = спринт. | Эталон, Политика |
| Scope freeze и фича-фриз дублировали друг друга. | Оставлен только фича-фриз в конце спринта; шаг Scope freeze удалён. | Эталон |
| Запуск аудита и работа с релиз-бордом были размазаны между ролями (Политика — Приходько; схема — Юрченко). | Вся цепочка релиз-борда (аудит → выкатка на UAT → функциональное тестирование → ПСИ ИБ → согласование трансфера) — в ЗО релиз-инженера НЕДРА; ИБ выполняет аудит, ПСИ и согласование. | Политика, схема |
| Go/No-Go создавал лишнее решение: после PreProd релиз всё равно идёт в Прод. | Go/No-Go убран. Правки после PreProd — только на уровне helm; критические дефекты включаются в hotfix. | Эталон |
| Не фиксировалась версия кода для аудита и выкатки. | Этап «Устранение багов и уязвимостей» заканчивается код-фризом (как в ДК); релиз-борд работает с зафиксированной версией. | Эталон, ДК |
| TOML готовился после ПТЗ (эталон) и сразу после финализации ветки (Политика). | TOML готовится параллельно регрессу на UAT и нужен к запуску аудита. | Эталон, Политика |
| RACI противоречил зонам ответственности: два «A» на этап, роль мейнтейнера отсутствовала. | Вместо RACI — единая таблица этапов: у каждого этапа один ответственный и перечень исполнителей. | Эталон |
| Кто принимает решение, было неясно. | Таблица «Шаг — ответственный» для всех решений. | Эталон |
| ПСИ целиком относили к ИБ. | ПСИ ИБ — ЗО релиз-инженера НЕДРА (запуск) и ИБ (проведение); бизнес-приёмка функционала — у ВНП (демо и PreProd). | Эталон |
| Hotfix описывался как «короткий паспорт» без ИБ-шагов. | Hotfix идёт тем же процессом, что плановый релиз. | Эталон, Политика |
| В ролях не было администраторов БД и брокеров, релиз-инженера НЕДРА, ВНП и РП по направлениям. | Роли и ФИО добавлены; для каждой роли описаны задачи цикла и полномочия по карточкам ролевой модели. | Политика, Доступы |
| ДК и календарь фиксировали даты без сервиса, исполнителя и результата. | ДК версия 2: этапы с ПЛАН/ФАКТ и таблица «релиз × сервис × этап». | ДК |
| В Jira не было единицы учёта для времени и ошибок. | Задача на каждый этап Релизного Epic, подзадача с полем «Сервис», возврат — новая задача. | Эталон, Jira |
| Роли списывались на проект как 1 FTE. | Правило: FTE по ТРЗ задач этапов; калькулятор «Роль — FTE — Стоимость». | Политика |
| У ряда ролей нет доступов (Юрченко, Грей, QA только по Оренбургу, админы БД и брокеров). | Проверка доступов до старта этапа (preflight) — в документе «Доступы для релизов». | Доступы |

## Остаётся подтвердить

- ПТЗ: в схему не включён (объединён с ПСИ ИБ в релиз-борде) — подтвердить, что отдельного ПТЗ больше нет.
- Значения SLA, которых нет в вашем перечне (подтверждение состава, скан, TOML, тест-план, выкатка на UAT, ПСИ ИБ, PreProd, Прод, коммуникация, закрытие).
- Слияние релизной ветки в master после выката — как техническая операция вне этапов процесса.
- Список сервисов и число сервисов в релизе (для расчёта FTE); ставки по ролям; часы по этапам в модели FTE.
- РП для ЕАРМ3 и ЕАРМ5; единое правило распределения багов UAT (ВНП или РП).
- Полная выгрузка столбцов ДК правее «Регресс» и доступы ролей по матрице.
