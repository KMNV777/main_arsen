## 2. Как составлять чек-лист по документации аналитика

Перед тем как писать пункты, пройдитесь по документации и зафиксируйте:

- [ ] Прочитана цель фичи и бизнес-ценность
- [ ] Определены все роли / типы пользователей
- [ ] Выписаны все функциональные требования (FR)
- [ ] Выписаны все нефункциональные требования (NFR)
- [ ] Разобраны все пользовательские сценарии (happy path)
- [ ] Разобраны альтернативные и ошибочные сценарии
- [ ] Сверены макеты и текстовые описания (расхождения — в вопросы)
- [ ] Разобран API-контракт: методы, коды ответов, поля, обязательность
- [ ] Определены граничные значения и бизнес-ограничения
- [ ] Определены интеграции (внешние/внутренние системы)
- [ ] Определены требования к логированию / аналитике / метрикам
- [ ] Определены требования по безопасности и доступам
- [ ] Определены требования по локализации / валютам / таймзонам
- [ ] Зафиксирован список открытых вопросов к аналитику
- [ ] Согласован scope тестирования (что тестируем, что — нет)

## 4. Шаблон чек-листа

> Для каждого пункта используйте статусы: `☐ not run`, `✅ pass`, `❌ fail`, `⚠️ blocked`, `➖ n/a`.
> К упавшим пунктам прикладывайте ссылку на баг.

### 4.1. Позитивные сценарии (happy path)

- [ ] Сценарий 1: <краткое описание из ТЗ>
  - Предусловия:
  - Шаги:
  - Ожидаемый результат (из документации, пункт §__):
- [ ] Сценарий 2: ...
- [ ] Сценарий 3: ...

### 4.2. Негативные сценарии

- [ ] Обязательные поля не заполнены → корректная ошибка
- [ ] Невалидный формат данных (email, телефон, дата, число) → ошибка
- [ ] Превышение длины полей (min / max из спеки)
- [ ] Недопустимые символы / инъекции (`<script>`, SQL, emoji, RTL)
- [ ] Отсутствие прав / неавторизованный пользователь
- [ ] Отсутствие соединения / таймаут внешнего сервиса
- [ ] Дубликаты / повторные отправки формы (double submit)
- [ ] Конкурентное редактирование одной сущности

### 4.3. Граничные значения

- [ ] Минимальное допустимое значение
- [ ] Максимальное допустимое значение
- [ ] Значение на единицу меньше минимума → отказ
- [ ] Значение на единицу больше максимума → отказ
- [ ] Ноль / пусто / null / undefined
- [ ] Отрицательные значения (если применимо)
- [ ] Очень большие объёмы данных (длинные списки, файлы)

### 4.4. UI / UX (по макетам)

- [ ] Соответствие макету: отступы, шрифты, цвета, иконки
- [ ] Состояния элементов: default / hover / focus / active / disabled / loading / error
- [ ] Состояния экранов: empty / loading / partial / error / success
- [ ] Валидация полей в реальном времени и на сабмите
- [ ] Тексты ошибок и подсказок совпадают с документацией
- [ ] Плейсхолдеры, лейблы, заголовки
- [ ] Поведение клавиатуры: Tab-порядок, Enter, Esc
- [ ] Фокус и доступность (a11y): роли ARIA, контраст, alt-тексты
- [ ] Адаптив: desktop / tablet / mobile (указать breakpoints)
- [ ] Поддерживаемые браузеры: Chrome / Firefox / Safari / Edge
- [ ] Тёмная / светлая тема (если применимо)
- [ ] Локализация: RU / EN / … — длинные строки не ломают вёрстку

### 4.5. Бизнес-логика (из требований аналитика)

- [ ] FR-1: <требование> — проверка
- [ ] FR-2: ...
- [ ] FR-3: ...
- [ ] Расчёты / формулы соответствуют ТЗ (приложить тестовые данные)
- [ ] Статусы сущности и переходы между ними соответствуют state-диаграмме
- [ ] Права ролей: что видит/может каждая роль
- [ ] Ограничения по количеству / лимитам / квотам

### 4.6. API / интеграции

- [ ] Эндпоинт `METHOD /path` — 2xx на валидный запрос
- [ ] Структура ответа соответствует контракту (поля, типы, обязательность)
- [ ] Коды ошибок: 400 / 401 / 403 / 404 / 409 / 422 / 429 / 5xx
- [ ] Валидация тела запроса (отсутствующие/лишние поля)
- [ ] Идемпотентность (для `PUT` / `DELETE` / повторных `POST` с ключом)
- [ ] Пагинация / сортировка / фильтрация
- [ ] Авторизация: токен, срок жизни, refresh, отзыв
- [ ] Соответствие версии API (v1 / v2)
- [ ] Вебхуки / события: отправка, ретраи, подпись
- [ ] Интеграция со смежной системой X — корректный обмен

### 4.7. Данные и БД

- [ ] Данные сохраняются корректно (все поля)
- [ ] Данные не теряются после перезагрузки / перелогина
- [ ] Миграции применяются / откатываются без потерь
- [ ] Мягкое / жёсткое удаление работает по ТЗ
- [ ] Аудит / история изменений (если требуется)

### 4.8. Нефункциональные требования

- [ ] Производительность: время ответа укладывается в SLA (указать)
- [ ] Нагрузка: поведение при N одновременных пользователях
- [ ] Безопасность: OWASP Top-10 по соответствующим пунктам
- [ ] Персональные данные обрабатываются согласно политике
- [ ] Логи не содержат секретов / PII
- [ ] Метрики и алерты настроены (ссылка на дашборд)
- [ ] Документация / релиз-ноуты обновлены

### 4.9. Регресс

- [ ] Смежные экраны / фичи не сломаны
- [ ] Основные пользовательские флоу (smoke) проходят
- [ ] Проверены фичи, использующие изменённые API/модели
