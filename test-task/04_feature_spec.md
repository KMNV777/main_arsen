# Задание 4. Мини‑ТЗ для программиста — Загрузка Грузового Шаттла

> Документ описывает **только часть** «загрузка ресурса в слот Шаттла» — аналог одного «вагона» в Township. Скоуп ограничен функциональностью одного слота и одной кнопки «Загрузить».

- **Платформа:** Mobile (iOS/Android), движок — текущий (Unity).
- **Версия фичи:** v0.1 — MVP загрузки одного слота.
- **Не входит в скоуп:** запуск шаттла, кулдаун, награды, песчаные бури, балансировка веса (см. отдельные ТЗ).

---

## 4.1. Контекст

Игрок открывает экран Шаттла со стартовой площадки. На экране — Шаттл и **6 слотов трюма**. В каждом слоте задан **запрос**: какой ресурс и сколько нужно. Игрок должен закрыть слот, передавая ресурсы со склада в трюм. Этот документ описывает поведение **одного** слота.

## 4.2. Что видит игрок (UI слота)

Один **Cargo Slot** содержит:

| Элемент | Описание |
|---------|----------|
| **Иконка ресурса** | 96×96 px, тянется из `ResourceConfig` по `resourceId`. |
| **Название ресурса** | Локализованная строка под иконкой (1 строка, обрезается с `...`). |
| **Счётчик «нужно / есть»** | Текст вида `3 / 5`, где `3` — `playerStock[resourceId]`, `5` — `slot.required`. |
| **Прогресс‑бар** | Заполняется по формуле `min(playerStock, required) / required`. |
| **Кнопка «Загрузить»** | Один из трёх стейтов (см. 4.4). |
| **Бейдж ✓ при заполнении** | Появляется поверх слота, когда `slot.loaded == slot.required`. |

ASCII‑набросок одного слота:

```
 ┌──────────────────────────┐
 │   [icon 96x96]           │
 │   Frozen Methane         │
 │   ▓▓▓▓▓░░░░░  3 / 5      │
 │   [   Загрузить   ]      │
 └──────────────────────────┘
```

## 4.3. На какую кнопку нажимает игрок

Главное действие — кнопка **«Загрузить»** (`btn_load`) в карточке слота.

- Тап по кнопке = «положить в этот слот **всё, что нужно** или столько, сколько есть на складе».
- Long‑press / drag не поддерживается в v0.1 (зафиксировано умышленно — упрощение MVP).

Дополнительные кнопки на этом экране (вне MVP скоупа, но для контекста):
- `btn_buy_missing` — появляется только в стейте «Missing» (см. 4.4 c).
- `btn_close` — закрыть экран Шаттла без последствий, прогресс слотов сохранён.

## 4.4. Состояния кнопки «Загрузить»

| Стейт | Условие | Вид кнопки | Поведение по тапу |
|-------|---------|------------|--------------------|
| **a) Available** | `playerStock >= slot.required` и `slot.loaded < slot.required` | Зелёная, активная, лейбл `Загрузить` | Грузим `delta = required - loaded`. |
| **b) Partial** | `0 < playerStock < (slot.required - slot.loaded)` | Жёлтая, активная, лейбл `Загрузить (частично)` | Грузим `delta = playerStock`. После — слот переходит в стейт **c**. |
| **c) Missing** | `playerStock == 0` и `slot.loaded < slot.required` | Серая, **неактивная**. Рядом появляется `btn_buy_missing` с ценой в Helium‑3 | Тап по `btn_buy_missing` → подтверждение покупки → списание Helium‑3 → автоматическая загрузка `delta = required - loaded`. |
| **d) Done** | `slot.loaded == slot.required` | Скрыта; вместо неё бейдж `✓ Загружено` | Тап по слоту = ничего, только лёгкий tooltip. |

## 4.5. Что происходит, если ресурса не хватает

Сценарий: игрок видит слот «нужно 5», на складе **0** Кристаллов замёрзшего метана.

1. Кнопка `Загрузить` находится в стейте **Missing** — серая, неактивна. Тап вызывает шейк‑анимацию + всплывающую подсказку: «Недостаточно ресурса. Произведите его на шахте или купите за Helium‑3».
2. Параллельно появляется **`btn_buy_missing`** с подписью `Купить (5) за 💎 50 He‑3`.
   - Цена считается формулой `price = missingAmount * resourceConfig.he3PricePerUnit`.
3. Тап `btn_buy_missing` → модальное окно подтверждения:
   - Кнопки `Отмена` / `Купить`.
   - Если у игрока **достаточно Helium‑3** → списание + автозагрузка `delta = required - loaded`. Слот переходит в стейт **Done**.
   - Если Helium‑3 **тоже не хватает** → открывается стандартный экран **Premium Shop** (out of scope v0.1, но `OpenShop(reason="he3_short")` уже надо вызвать). Игрок может купить He‑3 → вернуться → повторить покупку.
4. Если игрок отменил окно — стейт слота остаётся **Missing**, прогресс не теряется.

> Edge‑case: пока открыто модальное окно покупки, склад мог получить ресурс по таймеру производства (фабрика выдала готовый кристалл). На закрытии окна **обязательно пересчитываем стейт кнопки** (стейт может из «Missing» уехать в «Available»).

## 4.6. Псевдокод обработки тапа

```pseudo
function onLoadButtonTap(slot):
    if slot.loaded >= slot.required:
        return  # Done state, no-op

    available = playerInventory.get(slot.resourceId)
    if available <= 0:
        showTooltip("not_enough_resource")
        return

    delta = min(available, slot.required - slot.loaded)
    playerInventory.remove(slot.resourceId, delta)
    slot.loaded += delta

    saveProgress(shuttle)
    refreshSlotUI(slot)
    Analytics.log("shuttle_slot_loaded",
                  resourceId=slot.resourceId,
                  delta=delta,
                  remaining=slot.required - slot.loaded)

    if slot.loaded == slot.required:
        playSfx("slot_complete")
        playVfx("checkmark_pop", slot.position)
        emit Event.SlotCompleted(slot)
```

## 4.7. Структура данных

```ts
type ResourceId = string;

type CargoSlot = {
  slotIndex: 0..5;
  resourceId: ResourceId;
  required: int;        // задаётся конфигом текущего шаттла
  loaded: int;          // 0..required, персистится
};

type Shuttle = {
  shuttleId: string;
  slots: CargoSlot[6];
  expiresAt: timestamp; // время, до которого надо отправить (в скоупе ≥ v0.2)
};
```

Конфиг ресурса (нужен для UI и покупки за He‑3):

```ts
type ResourceConfig = {
  id: ResourceId;
  iconPath: string;
  locKey: string;
  he3PricePerUnit: int;
};
```

## 4.8. Аналитика (минимальный набор для MVP)

## 4.9. Acceptance Criteria

1. На открытии экрана UI каждого слота строится за < 200 мс на baseline‑девайсе.
2. Кнопка `Загрузить` корректно отображает один из 4 стейтов (Available / Partial / Missing / Done) и переключается **синхронно** после изменения склада.
3. При нехватке ресурса появляется `btn_buy_missing`, цена считается верно по формуле из 4.5.
4. Покупка за He‑3 атомарна: либо списались валюта **и** ресурс попал в слот, либо ничего не изменилось (на падении сети — откат).
5. Прогресс слота персистится: kill app → reopen → `loaded` сохраняется.
6. Все 6 событий аналитики стреляют согласно таблице 4.8.
7. Локализация: все строки берутся из `locKey`, нет хардкода в коде.

## 4.10. Открытые вопросы для GD/PM (вне скоупа MVP)

- Можно ли **выгружать** ресурс из слота обратно? (В Township — нельзя; предлагаю сохранить это правило, чтобы «Загрузить» был коммит‑экшеном.)
- Должны ли слоты иметь индивидуальный таймер или таймер общий на весь Шаттл? (Решаем в задании по «Запуску Шаттла».)
- Где показывать `btn_buy_missing`: в карточке слота или в общем футере экрана? (UX‑вопрос, требует прототипа.)
