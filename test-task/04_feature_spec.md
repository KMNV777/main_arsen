# Задание 4. ТЗ для программиста — Загрузка Грузового Шаттла (полный флоу)

> Документ описывает **полный флоу загрузки**, как в Township (Trains): от появления нового шаттла на станции до его отправки и кулдауна. Скоуп — функциональность, которую игрок видит и щёлкает; экономика наград и баланс — отдельный документ.

- **Платформа:** Mobile (iOS/Android), движок — Unity.
- **Версия:** v1.0 — первый полный релиз фичи «Грузовой Шаттл».
- **Связанные документы:** [01 — реверс‑инжиниринг Township](./01_reverse_engineering.md), [02 — адаптация под сеттинг](./02_setting_adaptation.md), [03 — визуальный бриф](./03_visual_brief.md).

## 4.1. Глоссарий

| Термин | Что значит |
|--------|------------|
| **Шаттл** | Сущность, аналог поезда из Township. Содержит трюм из 6 слотов. |
| **Cargo Slot (слот)** | Одна ячейка трюма с конкретным запросом (ресурс + количество). |
| **Запрос** | `{resourceId, required}`. Задаётся конфигом при генерации шаттла. |
| **Загружено / `loaded`** | Сколько игрок уже положил в слот. `0 ≤ loaded ≤ required`. |
| **Склад / `playerStock`** | Текущее количество ресурса в инвентаре игрока. |
| **He‑3 (Helium‑3)** | Премиум‑валюта (см. задание 2). |
| **Кредиты** | Мягкая валюта. |

## 4.2. Прямой ответ на 3 вопроса брифа

### 1) Что видит игрок?

При открытии экрана Шаттла игрок видит **6 cargo‑слотов**, в каждом:

- **Иконка ресурса** (96×96 px из `ResourceConfig.iconPath`).
- **Название ресурса** (1 строка, локализовано).
- **Счётчик прогресса** в формате `loaded / required` (например, `3 / 5`).
- **Прогресс‑бар** под счётчиком: `min(playerStock + loaded, required) / required`.
- **Малый счётчик «у тебя»** под счётчиком прогресса: `playerStock` ресурса на складе. Если `playerStock = 0` — подсветка красным.
- **Кнопка действия**: «Загрузить» / «Загрузить (частично)» / «Купить» / бейдж `✓` (см. 4.5).

Над трюмом — **общий хедер шаттла**: имя/код шаттла, общий прогресс `X / 6 слотов закрыто`, **таймер срока отправки** (если есть), кнопка `Отправить` (активна только когда все 6 слотов закрыты).

### 2) На какие кнопки нажимает?

Главные интерактивы экрана:

| Кнопка | Где | Когда активна | Что делает |
|--------|-----|----------------|-------------|
| **«Загрузить»** | В каждом слоте | `playerStock > 0` и `loaded < required` | Грузит `min(playerStock, required − loaded)` в этот слот. |
| **«Купить»** | В каждом слоте, заменяет «Загрузить» | `playerStock < required − loaded` | Открывает диалог покупки недостающего за He‑3. |
| **«Отправить» (главная)** | Хедер шаттла | Все 6 слотов `loaded == required` | Запускает шаттл, начинает кулдаун. |
| **«Помощь альянса»** | Хедер шаттла | После хотя бы 1 действия игрока | Один раз на шаттл — попросить альянс прислать недостающие ресурсы. |
| **«Скип кулдауна»** | На станции, во время полёта | `state == InTransit` | За He‑3 мгновенно завершает полёт. |
| **«Забрать награду»** | Окно после возврата | `state == Returned` | Зачисляет награду, возвращает шаттл в Idle. |
| **«Закрыть»** | Везде | Всегда | Возвращает на карту фермы. Прогресс по слотам сохраняется. |

### 3) Что происходит, если ресурса не хватает?

Сценарий «нужно 5, на складе 0»:

1. Кнопка «Загрузить» в слоте **превращается в кнопку «Купить (5) за 💎 50 He‑3»**. Базовая «Загрузить» неактивна / скрыта.
2. Малый счётчик `у тебя: 0` подсвечивается красным.
3. Тап «Купить» → модалка подтверждения с 2 кнопками `Отмена` / `Купить`.
   - Если **He‑3 хватает** → списание He‑3 → автозагрузка `delta = required − loaded` → слот переходит в `Done`.
   - Если **He‑3 не хватает** → редирект в Premium Shop с `reason="he3_short"`. После пополнения игрок возвращается, повторяет покупку.
4. Тап «Отмена» → ничего не списано, прогресс слота сохранён.

Сценарий «нужно 5, на складе 2» (частично хватает):

1. Кнопка слота показывает **«Загрузить (частично) +2»**. Цвет — жёлтый.
2. Тап → грузит 2 → `loaded = 2`, `playerStock = 0`.
3. Кнопка перерисовывается в **«Купить (3) за He‑3»** — игрок может купить остаток или пойти производить.

Дополнительные пути решения нехватки (помимо покупки за He‑3):

- **Произвести на ферме / в шахтах.** Тап по иконке ресурса в слоте → переход на здание‑производитель (deeplink), где можно поставить производство в очередь. Прогресс слота сохранён.
- **Запросить у альянса.** Кнопка «Помощь альянса» в хедере. Раз в шаттл. Союзники видят запрос в общем чате, могут отправить до N единиц каждого недостающего ресурса.
- **Подождать.** Если у шаттла есть таймер срока — игрок видит, сколько у него ещё есть времени.

## 4.3. Состояния шаттла (state machine)

| Состояние | Условие | Что показывает UI на станции | Допустимые действия |
|-----------|---------|------------------------------|----------------------|
| **`Idle`** | Шаттл не запрошен / уже улетел и ещё не вернулся | Пустая площадка, бейдж «!» если новый запрос ждёт активации | Тап → переход в `Loading` (генерация запроса) |
| **`Loading`** | Шаттл стоит, есть активный запрос, не все слоты закрыты | Шаттл на полосе, индикатор `0..6/6` | Открыть экран загрузки |
| **`Ready`** | Все слоты закрыты, ждёт нажатия «Отправить» | Зелёный glow вокруг шаттла | Тап «Отправить» |
| **`Launching`** | Игрок нажал «Отправить» | Анимация старта T‑3..0, дым | Нет (анимация ~3 сек) |
| **`InTransit`** | Шаттл в полёте | Таймер обратного отсчёта на станции, мини‑карта траектории | Скип за He‑3 |
| **`Returned`** | Кулдаун закончился | Шаттл на полосе с лутбоксом, конфетти | Тап «Забрать награду» |
| **`Idle (cooldown_until_next)`** | Награда забрана | Площадка пустая, таймер «следующий запрос через …» | Ждать |

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Loading: появился запрос
    Loading --> Loading: load_slot / buy_missing
    Loading --> Ready: все 6 слотов закрыты
    Ready --> Loading: (теоретически невозможно — выгрузка запрещена)
    Ready --> Launching: tap «Отправить»
    Launching --> InTransit: анимация ~3с
    InTransit --> Returned: таймер истёк / скип
    Returned --> Idle: tap «Забрать награду»
```

## 4.4. Полный флоу игрока (happy path + ветки)

### 4.4.1. Появление запроса

1. По таймеру (или по первому входу) на станции активируется новый запрос. Бейдж «!» на иконке станции.
2. Тап по станции → открывается **экран Шаттла** (см. 4.5).
3. `Analytics: shuttle_request_opened {shuttleId, slotsConfig}`.

### 4.4.2. Загрузка слота (основной цикл)

Для каждого из 6 слотов игрок проходит микро‑цикл:

1. Смотрит, что нужно (иконка + `loaded / required`) и что есть (`playerStock`).
2. Жмёт «Загрузить» / «Купить» / уходит производить.
3. UI слота перерисовывается (см. 4.5).

### 4.4.3. Отправка

1. Когда все 6 слотов в `Done`, шаттл переходит в `Ready`. Кнопка «Отправить» в хедере становится активной (зелёная, пульсация).
2. Тап «Отправить» → модалка‑подтверждение **«Запустить шаттл? Грузы вернутся через 4ч»**, с 2 кнопками `Отмена` / `Запустить`.
3. Тап `Запустить` → шаттл уходит в `Launching` → анимация старта (T‑3..0, дым, звук) → `InTransit`.
4. **С этого момента**: загруженные ресурсы списаны окончательно (точка коммита).
5. `Analytics: shuttle_launched {shuttleId, totalCargo, slotsConfig, timeSinceOpened}`.

### 4.4.4. Кулдаун / полёт

1. На станции таймер `HH:MM:SS`. Тап по станции → мини‑экран статуса полёта с траекторией Марс ↔ Olympus‑1.
2. Кнопка `Скип за 💎 He‑3` (цена линейно зависит от оставшегося времени).
3. По истечению таймера → `Returned`. Push‑нотификация «Шаттл вернулся!».

### 4.4.5. Получение награды

1. На станции бейдж `🎁`. Тап → экран наград.
2. Анимация «лутбокс открывается», 1‑за‑1 показываются полученные предметы (запчасти, чертежи, семена, He‑3, кредиты).
3. Тап `Забрать всё` → ресурсы зачисляются на склад / в коллекции, шаттл уходит в `Idle`.
4. `Analytics: shuttle_reward_claimed {shuttleId, items[]}`.
5. Через `nextRequestDelay` (конфиг) станция снова активируется → новый шаттл.

### 4.4.6. Ветки и крайние случаи

| Ситуация | Поведение |
|----------|-----------|
| Игрок закрыл экран не догрузив | Прогресс слотов сохранён. На станции виден прогресс‑бейдж `2/6`. |
| Игрок убил приложение | Всё персистится: `loaded` по слотам, состояние шаттла, серверный таймер кулдауна. |
| Сервер недоступен в момент тапа «Загрузить» | Локальный оптимистичный апдейт UI + queued‑request. При неудаче через 5 сек — откат + тост «Не удалось загрузить, попробуй ещё раз». |
| Игрок сменил устройство / переустановил | Состояние шаттла — на сервере, восстанавливается при логине. |
| У шаттла истёк таймер срока (если включён) | Шаттл сгорает, загруженные ресурсы возвращаются на склад −20% (штраф). Запрос обнуляется. |
| Игрок запросил помощь альянса, союзник прислал ресурс | Ресурс падает на склад → перерисовка UI слота (стейт может перейти из `Missing` в `Available`). |

### 4.5.2. Карточка слота — стейты кнопки действия

| Стейт | Условие | Кнопка | Доп.‑элементы | По тапу |
|-------|---------|--------|----------------|----------|
| **Available** | `playerStock ≥ required − loaded` и `loaded < required` | Зелёная `Загрузить` | — | `delta = required − loaded`. Перевод в `Done`. |
| **Partial** | `0 < playerStock < required − loaded` | Жёлтая `Загрузить (+N)` | — | `delta = playerStock`. Перевод в `Missing`. |
| **Missing** | `playerStock == 0` и `loaded < required` | Серая «Загрузить» (disabled) **+** синяя `Купить (N) за 💎` | Красный счётчик «у тебя: 0», deeplink‑тап по иконке ресурса → здание‑производитель | Тап `Купить` → диалог покупки (см. 4.6). |
| **Done** | `loaded == required` | — (заменена бейджем `✓ Готово`) | Карточка слегка «состарена», прогресс‑бар полный | Нет действия (tooltip «Слот заполнен»). |

### 4.5.3. Хедер

- **Имя шаттла**, например `Mariner‑7` (генерируется из пула).
- **Таймер срока** (опционально, если у шаттла есть deadline) — `HH:MM:SS`. При истечении — состояние `Expired` (см. 4.4.6).
- **Прогресс шаттла** `X/6` слотов закрыто.
- **Кнопка `×`** — закрыть экран, вернуться на ферму.

### 4.5.4. Футер

- **«Помощь альянса»** — активна, пока запрос ещё не отправлен и игрок состоит в альянсе. Доступна 1 раз на шаттл.
- **«Отправить»** — активна только в `Ready`. До этого серая, по тапу — тост «Закрой все 6 слотов».

## 4.7. Серверная и клиентская логика

### 4.7.1. Источник правды

- **Конфиг шаттла** (что нужно, deadline, награды) — серверный, прилетает при `GET /shuttle/current`.
- **Состояние** (`loaded` по слотам, фаза, таймеры) — серверное, клиент кэширует.
- **Cклад игрока** — серверный.

### 4.7.2. Атомарные операции

Все операции, меняющие склад и состояние, выполняются одним серверным запросом и атомарны:

| Операция | Серверный эндпоинт | Что меняет |
|----------|---------------------|------------|
| Загрузить слот | `POST /shuttle/{id}/load` `{slotIndex, amount}` | `playerStock −= amount`, `slot.loaded += amount` |
| Купить недостающее | `POST /shuttle/{id}/buy` `{slotIndex}` | `playerHe3 −= price`, `slot.loaded = required` |
| Запросить помощь | `POST /shuttle/{id}/ask_help` | флаг `helpRequested = true`, рассылка в альянс |
| Отправить шаттл | `POST /shuttle/{id}/launch` | `state = InTransit`, `arriveAt = now + cooldown` |
| Скип кулдауна | `POST /shuttle/{id}/skip` | `playerHe3 −= price`, `state = Returned` |
| Забрать награду | `POST /shuttle/{id}/claim` | склад `+= reward`, `state = Idle` |

### 4.7.3. Клиентский псевдокод обработки тапа «Загрузить»

```pseudo
function onLoadTap(slot):
    if slot.state == Done: return
    if playerStock[slot.resourceId] <= 0:
        showTooltip("not_enough_resource"); return

    delta = min(playerStock[slot.resourceId], slot.required - slot.loaded)

    optimistic:
        playerStock[slot.resourceId] -= delta
        slot.loaded += delta
        refreshSlot(slot); refreshShuttleHeader()

    api.post(`/shuttle/${shuttleId}/load`, {slotIndex, amount: delta})
        .onSuccess: applyServerState(response)
        .onError:
            rollbackOptimistic()
            toast("Не удалось загрузить, попробуй ещё раз")

    Analytics.log("shuttle_slot_loaded", {shuttleId, slotIndex, resourceId, delta})

    if slot.loaded == slot.required:
        playSfx("slot_complete"); playVfx("checkmark_pop", slot.position)
        if allSlotsDone(): onShuttleReady()
```

### 4.7.4. Структуры данных

```ts
type ResourceId = string;

type CargoSlot = {
  slotIndex: 0 | 1 | 2 | 3 | 4 | 5;
  resourceId: ResourceId;
  required: int;        // immutable после генерации
  loaded: int;          // 0..required
};

type Shuttle = {
  shuttleId: string;
  shuttleName: string;
  slots: CargoSlot[6];
  state: "Idle" | "Loading" | "Ready" | "Launching" | "InTransit" | "Returned";
  expiresAt?: timestamp; // дедлайн отправки (опционально)
  arriveAt?:  timestamp; // конец кулдауна, если InTransit
  rewardConfig: RewardConfig;
  helpRequested: bool;
};

type ResourceConfig = {
  id: ResourceId;
  iconPath: string;
  locKey: string;
  he3PricePerUnit: int;
  producerBuildingId: string; // для deeplink из карточки слота
};
```

## 4.9. Acceptance Criteria

1. На открытии экрана шаттла UI всех 6 слотов и хедера строится за < 250 мс на baseline‑девайсе.
2. Каждый слот корректно отображает один из 4 стейтов (Available / Partial / Missing / Done) и переключается **синхронно** при изменении склада или после ответа сервера.
3. При нехватке ресурса появляется кнопка `Купить за He‑3`; цена считается по `missing × he3PricePerUnit`.
4. Покупка за He‑3 атомарна: либо списались валюта **и** ресурс зачислен в слот, либо ничего не изменилось (на ошибке сети — откат и тост).
5. Кнопка `Отправить` активна **только** когда все 6 слотов в `Done`, и неактивна в любом другом случае.
6. После `Отправить` ресурсы окончательно списаны, а UI шаттла переходит в анимацию `Launching` → `InTransit` без дополнительных тапов.
7. Прогресс слотов и состояние шаттла **персистятся**: kill app → reopen → данные восстановлены с сервера, UI идентичен.
8. Скип кулдауна за He‑3 корректно мгновенно завершает таймер и переводит шаттл в `Returned`.
9. Запрос помощи альянса доступен **ровно один раз** на шаттл и недоступен после `Отправить`.
10. Все события аналитики из таблицы 4.8 стреляют согласно своим триггерам.
11. Все строки UI берутся из `locKey` — нет хардкода в коде.
12. Deeplink из карточки слота на здание‑производитель работает корректно: возвращает игрока обратно на экран шаттла кнопкой «назад» с сохранением прогресса.

## 4.10. Открытые вопросы для GD/PM

- Можно ли **выгружать** ресурс из слота обратно? **Решение по умолчанию:** нет (как в Township) — это держит «загрузить» как commit‑экшен и не ломает экономику.
- Должен ли быть **общий таймер срока** на шаттл или таймер на слот? **Решение по умолчанию:** общий, как в Township; срок включаем только на ивент‑шаттлах.
- Сколько слотов нужно сделать на старте — 6 или 9? **Решение по умолчанию:** 6 (3+3, см. задание 2 — это нужно для будущей балансировки веса).
- Где показывать кнопку `Купить за He‑3`: в карточке слота или в общем футере экрана? **Решение по умолчанию:** в карточке слота — даёт более прицельную монетизацию и понятнее игроку «за что плачу».
