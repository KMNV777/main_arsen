# Задание 4. ТЗ для программиста — Загрузка Шаттла (часть функциональности)

> Документ описывает **часть** фичи «Грузовой Шаттл» — экран загрузки и взаимодействие игрока с одним cargo‑слотом. Это прямой аналог загрузки одного «вагона» в Township. Запуск шаттла, кулдаун и награды — отдельные документы.

- **Платформа:** Mobile (iOS/Android), Unity.
- **Входная точка:** игрок нажимает на станцию шаттла на карте фермы → открывается **Экран загрузки**.
- **Не входит в скоуп:** анимация старта, таймеры полёта, экран наград, помощь альянса.

---

## 4.1. Прямой ответ на 3 вопроса брифа

### 1) Что видит игрок?

При открытии экрана игрок видит **карточку cargo‑слота** (для MVP — один слот; в проде их 6, верстаются одной и той же компонентой). В карточке:

- **Иконка ресурса** — 96×96 px из `ResourceConfig.iconPath`.
- **Название ресурса** — 1 строка, локализовано (например, «Кристалл замёрзшего метана»).
- **Сколько нужно** — крупным числом, формат `loaded / required` (например, `3 / 5`).
- **Сколько есть у игрока** — мелкой строкой ниже, формат `У тебя: N` (тянется из `playerStock[resourceId]`). Если `N == 0` — текст красный.
- **Прогресс‑бар** под счётчиком: заполняется по `loaded / required`.
- **Кнопка действия** — её состояние зависит от соотношения «нужно / есть» (см. вопрос 2).
- **Бейдж `✓ Готово`** — появляется поверх карточки, когда `loaded == required`.

ASCII‑макет одной карточки:

```
 ┌──────────────────────────────┐
 │       [ icon 96×96 ]         │
 │   Кристалл замёрзшего метана │
 │                              │
 │       3 / 5                  │
 │   ▓▓▓▓▓▓░░░░░░               │
 │   У тебя: 2                  │
 │                              │
 │   [    Загрузить    ]        │
 └──────────────────────────────┘
```

### 2) На какие кнопки нажимает?

Главное действие — кнопка **«Загрузить»** в карточке слота. Она имеет **4 состояния** в зависимости от текущего `playerStock`:

| Стейт | Условие | Вид кнопки | Что делает по тапу |
|-------|---------|------------|---------------------|
| **a) Available** | `playerStock ≥ required − loaded` | Зелёная, `Загрузить` | Грузит `delta = required − loaded` → слот сразу в `Done`. |
| **b) Partial** | `0 < playerStock < required − loaded` | Жёлтая, `Загрузить (+N)`, где `N = playerStock` | Грузит `delta = playerStock` → слот переходит в `Missing`. |
| **c) Missing** | `playerStock == 0` и `loaded < required` | Серая (disabled). Рядом появляется синяя `Купить (N) за 💎 He‑3` | Тап `Купить` → диалог покупки за премиум‑валюту (см. вопрос 3). |
| **d) Done** | `loaded == required` | Скрыта; вместо неё бейдж `✓ Готово` | Тап ничего не делает (тултип «Слот заполнен»). |

> Дополнительно: тап по **иконке ресурса** в карточке — это deeplink на здание‑производитель. Игрок попадает на нужную фабрику и может поставить производство в очередь, прогресс слота сохранён.

Вне карточки слота на экране есть только:
- **Кнопка `×`** (закрыть экран, прогресс сохранён).
- **Кнопка `Отправить`** в футере — вне скоупа этого ТЗ, но активна только когда все 6 слотов в `Done`.

### 3) Что происходит, если ресурса не хватает?

Сценарий: «нужно 5, на складе 0».

1. Кнопка `Загрузить` уходит в стейт **Missing** — серая, неактивна. Тап по ней даёт лёгкую шейк‑анимацию и тултип: «Не хватает ресурса. Произведи на ферме или купи за He‑3».
2. Рядом с ней появляется **`Купить (5) за 💎 50 He‑3`**. Цена считается формулой `price = missing × resourceConfig.he3PricePerUnit`.
3. Малый счётчик `У тебя: 0` подсвечен красным.
4. Тап `Купить` открывает **диалог подтверждения**:
   - Если **He‑3 хватает** (`playerHe3 ≥ price`) → две кнопки `Отмена` / `Купить`. На `Купить`: атомарно `playerHe3 −= price` и `slot.loaded = required`. Слот → `Done`.
   - Если **He‑3 не хватает** (`playerHe3 < price`) → кнопка `Купить` подменяется на `+ Пополнить`, ведёт в Premium Shop с `reason="he3_short"`. После пополнения игрок возвращается, повторяет покупку.
5. Тап `Отмена` или закрытие диалога → ничего не списано, прогресс слота сохранён.

**Альтернативные пути решения нехватки** (без покупки):
- Пойти на ферму через deeplink с иконки и **произвести** ресурс.
- Закрыть экран, вернуться позже — прогресс слота персистится.

**Edge‑case:** пока открыт диалог покупки, склад мог пополниться (фабрика выдала готовый ресурс по таймеру). На закрытии диалога **обязательно пересчитываем** стейт кнопки — он мог уехать из `Missing` в `Available`.

## 4.2. Псевдокод обработчика тапа «Загрузить»

```pseudo
function onLoadButtonTap(slot):
    if slot.loaded >= slot.required:
        return  // Done — no-op

    available = playerInventory.get(slot.resourceId)
    if available <= 0:
        showTooltip("not_enough_resource")
        return

    delta = min(available, slot.required - slot.loaded)

    playerInventory.remove(slot.resourceId, delta)
    slot.loaded += delta

    persistProgress(slot)
    refreshSlotUI(slot)

    if slot.loaded == slot.required:
        playSfx("slot_complete")
        playVfx("checkmark_pop", slot.position)
        emit Event.SlotCompleted(slot)
```

И обработчик тапа «Купить»:

```pseudo
function onBuyButtonTap(slot):
    missing = slot.required - slot.loaded
    price = missing * resourceConfig[slot.resourceId].he3PricePerUnit

    if playerHe3 < price:
        openShop(reason="he3_short", needed=price - playerHe3)
        return

    showConfirmDialog(price, missing) -> confirmed:
        if not confirmed: return

        // атомарно: либо обе операции, либо ни одна
        transaction:
            playerHe3 -= price
            slot.loaded = slot.required

        persistProgress(slot)
        refreshSlotUI(slot)
        playSfx("slot_complete")
```

## 4.3. Структуры данных

```ts
type ResourceId = string;

type CargoSlot = {
  slotIndex: number;       // 0..5
  resourceId: ResourceId;
  required: number;        // immutable, задаётся конфигом шаттла
  loaded: number;          // 0..required, персистится
};

type ResourceConfig = {
  id: ResourceId;
  iconPath: string;
  locKey: string;          // ключ локализации названия
  he3PricePerUnit: number; // цена 1 единицы при покупке за He-3
  producerBuildingId: string; // для deeplink с иконки
};
```

## 4.4. Acceptance Criteria

1. На открытии экрана UI карточки слота строится за < 200 мс на baseline‑девайсе.
2. Карточка корректно отображает один из 4 стейтов кнопки (`Available` / `Partial` / `Missing` / `Done`) и переключается **синхронно** при изменении `playerStock`.
3. Счётчики `loaded / required` и `У тебя: N` обновляются сразу после успешной загрузки или покупки.
4. Когда ресурса не хватает, появляется кнопка `Купить за He‑3` с правильной ценой.
5. Покупка за He‑3 **атомарна**: либо валюта списалась **и** слот стал `Done`, либо ничего не изменилось.
6. Если He‑3 не хватает — открывается Premium Shop с `reason="he3_short"`, экран загрузки на фоне сохраняет прогресс.
7. Тап по иконке ресурса в карточке корректно ведёт на здание‑производитель и обратно с сохранением прогресса.
8. Прогресс слота персистится: kill app → reopen → `loaded` сохраняется.
9. Все строки UI берутся через `locKey` — нет хардкода.

## 4.5. Открытые вопросы

- Можно ли **выгружать** ресурс из слота обратно? **Решение по умолчанию:** нет (как в Township) — это сохраняет «Загрузить» как commit‑экшен.
- Кнопка `Купить за He‑3` — в карточке слота или в общем футере? **Решение по умолчанию:** в карточке — игрок понимает, за какой именно слот платит.
- Нужно ли подтверждение покупки за He‑3 при малых суммах (например, < 10 He‑3)? **Решение по умолчанию:** да, всегда — защита от случайного тапа на премиум‑валюту.
