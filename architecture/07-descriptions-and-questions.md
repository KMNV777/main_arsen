## 7.1. Описание схемы 01 — «Общий ИТ-ландшафт» (`01-overview.md`)

### Что изображено

Семислойная C4-style диаграмма, читается сверху вниз:

1. **Пользователи и потребители** — четыре крупные группы:
   - 2 947 пользователей ABAI в 8 ДЗО Upstream + Корпоративном центре;
   - 48 ДЗО + ДОТОС в ИСОТ (HSE);
   - 43 ДЗО в Compliance Control;
   - функциональные роли КЦ КМГ: Совет директоров и Правление (BoardMaps), HR/ДУЧР, PMO, Финансы, Legal, УДО, Закупки, PR;
   - внешние пользователи (карьерные кандидаты, посетители публичных сайтов).
2. **Внешние интеграции** разделены на два кластера:
   - **Государственные сервисы** (🏛️): ЕСЭДО, НУЦ РК (TSP и OCSP для ЭЦП), data.egov.kz, ГБД ЮЛ / ГБД ФЛ, nationalbank.kz.
   - **Коммерческие сервисы**: Commodities-API, Kompra, HikVision (отключено), Qsamruk.kz.
3. **Внутренние корпоративные источники** — мастера данных, которые сами по себе НЕ являются предметом учёта в реестре ДПППС, но определяют 70 % всех интеграционных потоков: SAP S/4HANA (АНПЗ/КМГ/Price/BP/АВР), 1С (ПНХЗ, ПКОП, Финансы/HR), MES Honeywell (АНПЗ/ПНХЗ), QlikSense Кумколь, SCADA-серверы ДЗО, ИШ/КХД/KMG DATA, ИСЭЗ, Active Directory КМГ, SMTP.
4. **Прикладной слой** — 20+ ИС, разбитых по 9 доменам (Upstream, Документооборот, Аналитика/PMO, HSE/Compliance/Eco, HR/Порталы, Закупки, Логистика, Корп. портал/сайты, Активы/Прочее).
5. **Интеграционный слой** — общеприложенческие компоненты: RabbitMQ/Kafka, Redis/Memcached/SharePoint Distributed Cache, HAProxy+keepalived, etcd (Patroni), ELK, Grafana+Prometheus (только в части ИС), GitLab on-prem. Здесь же явно выделены отсутствующие компоненты: API Gateway, circuit breaker, rate limiting, централизованный ETL.
6. **Данные** — шесть кластеров хранилищ (PostgreSQL, MS SQL, MySQL/MariaDB, MongoDB, BigData-стек внутри ABAI, объектные хранилища MinIO/SeaweedFS).
7. **Инфраструктура** — два VDC QazCloud (Koshy и Aqqol), On-Prem АНПЗ, локальная инфра ЭМГ, GPU-кластер 5×IBM POWER 9 + Tesla V100.

### Что эта схема позволяет увидеть

- Один-в-один читается «карта зависимостей»: например, видно, что Active Directory — единая точка входа практически для всех систем, и её недоступность блокирует SSO везде.
- Видно ровно одну точку, где гос-сектор уходит в архитектуру (ЕСЭДО → САПФИР каждые 10 мин по SOAP), и две точки ЭЦП (НУЦ РК → СДД и BoardMaps).
- BigData-стек (Druid/Spark/Kafka/Hadoop) изолирован внутри ABAI — другие системы его не переиспользуют.

### Уточняющие вопросы по схеме 01

1. **Корпоративная шина данных.** Есть ли в КМГ официальная корпоративная ESB / интеграционная шина (например, упомянутая в потоке ГБД ФЛ → Бюро пропусков «через ESB/КДП»)? Если есть — какие ИС её используют сейчас и почему не используются для остальных интеграций?
2. **Стратегия API Gateway.** Принято ли решение о выборе API Gateway (Kong / Apigee / WSO2 / KrakenD)? Какие системы окажутся первыми на миграцию?
3. **Распределение по VDC.** По какому критерию системы распределены между Koshy и Aqqol? Это исторически (миграция дата-центров) или по доменам безопасности?
4. **Сетевой контур.** Есть ли единая сетевая диаграмма между VDC, on-prem ДЗО и локальной инфрой ЭМГ? Какие VPN/IPsec туннели, каналы L2/L3 используются?
5. **DNS и доменная политика.** Почему часть сайтов на `kmg.kz`-поддомене (`hse.kmg.kz`, `pmo.kmg.kz`), часть — на отдельных доменах (`anpz.kz`, `kpi.kz`, `kmg-kumkol.kz`)? Кто администрирует DNS?
6. **DMZ.** Где находится DMZ-периметр для публичных сайтов (kmg.kz, kpi.kz)? Они в том же VDC, что и внутренние ИС?
7. **Цикл жизни ИС.** Есть ли единый реестр статусов (Plan → PoC → PROD → ВЫВОД → ОТКЛЮЧЕНО), привязанный к SAW/ServiceDesk? Сейчас статусы разбросаны по паспортам.
8. **Связи между ABAI и КМГИ-системами.** В документе упомянуты Petrel, Techlog, Т-Навигатор, Darcy — но они вне зоны ДПППС. Есть ли поток данных из них обратно в КМГ? Какие именно?

## 7.2. Описание схемы 02 — «Бизнес-домены и системы» (`02-domains.md`)

### Что изображено

9 «коробок»-доменов, в каждой — карточки ИС с тремя ключевыми блоками информации:
- название и статус (🟢/🟡/🔴);
- ссылка на домен и идентификатор SAW (где есть);
- стек: фронтенд, бэкенд, СУБД, очереди/кэш, ОС, особенности развёртывания.

Отдельно вынесен признак внешнего вендора (фиолетовый) — это:
- **САПФИР** (Directum Insarco / Directum RX),
- **BoardMaps** (ОАО «Дэшборд Системс»),
- **Bitrix-порталы и сайты** (1С-Битрикс24),
- **SharePoint-системы Интранета и ИСУП** (Microsoft).

### Что эта схема позволяет увидеть

- **Технологическое разнообразие очень велико**: 5 языков бэкенда (Python, Golang, C#/.NET, Node.js, PHP, Java), 4 фронтенд-фреймворка (Vue 2/3, React, Angular, SharePoint Web UI), 4 СУБД (PG / MS SQL / MySQL / Mongo). Это объясняет, почему в КМГ невозможна «единая платформа» в моменте.
- В одном домене встречаются разные технологические эпохи: например, **«Документооборот»** объединяет вендорский Directum (САПФИР), современный микросервисный СДД на Go+K8s, legacy-Documentum (ЭА), и закрытый вендорский BoardMaps.
- В домене **«Аналитика / PMO»** — две системы, целиком построенных на Microsoft-стеке (АСДЦ + ИСУП), причём АСДЦ — это «legacy mix» (AngularJS + Knockout + Razor + PHP + .NET + MS SQL 2014).
- **Bitrix24** — отдельная экосистема из 4 порталов (Team / ANPZ / Petrochem / КМКЛ) + 4 публичных сайтов; де-факто это «второй интранет КМГ» параллельно с SharePoint.

## 7.3. Описание схемы 03 — «Потоки интеграций» (`03-integrations.md`)

### Что изображено

Файл содержит **8 микро-диаграмм** интеграций (по основным «системам-хабам») + **сводную таблицу 44+ потоков**:

1. **ABAI** — самая длинная цепочка: SCADA ДЗО → MySQL ЭМГ → MySQL КТМ → MySQL SCADA сервер КМГ → ABAI (`abaiprot` в PG). Плюс внешние REST (data.egov.kz, Commodities-API) и SSO через AD.
2. **АСДЦ** — analytics-хаб с 7 источниками входящих (SAP АНПЗ, 1С ПНХЗ, 1С ПКОП, MES Honeywell АНПЗ, MES ПНХЗ, QlikSense Кумколь, nationalbank.kz) и 3 потребителями исходящих (ИШ, КХД, KMG DATA).
3. **САПФИР** — основной поток с ЕСЭДО (SOAP/XML каждые 10 мин), плюс AD/SMTP/Directum Ario.
4. **СДД** — самая «насыщенная» сертификатами/ЭЦП система: AD + SMTP + TSP + OCSP + SAP S/4HANA (Business Partner + АВР) + ИСЭЗ + Электронный архив.
5. **HR-кластер**: Team ↔ Work ↔ Qsamruk + Bitrix ANPZ → iJanet.
6. **Compliance Control** — Kompra (REST) + AD (раз в сутки) + SAP (SOAP 3×/сутки).
7. **Procu / Price** — SAP Price + ГБД ЮЛ.
8. **ИСУП и Интранет** — оба питаются AD (LDAP/NTLM) + Power BI для дашбордов ИСУП.

### Что эта схема позволяет увидеть

- **Архитектурный риск №1** — цепочка SCADA-буферов на dbLink: 4 переноса данных между MySQL, при сбое любого звена ABAI «слепнет» по телеметрии.
- **Архитектурный риск №2** — все интеграции — *point-to-point* через REST/SOAP **без API Gateway**. Это означает: нет единого места для аутентификации внешних вызовов, нет rate limiting, нет логирования трафика, нет circuit breaker. Падение НУЦ РК или ЕСЭДО мгновенно сваливает СДД/САПФИР.
- **АСДЦ — bottleneck**: 7 источников втягиваются по разным протоколам (SOAP, TCP/IP byte, HTTP/XML) и сохраняются в одну MS SQL 2014. Любое расширение требует доработки внутри устаревшего стека.
- **AD — universal LDAP target**: участвует в 12+ потоках; падение AD парализует SSO во всех системах.

## 7.4. Описание схемы 04 — «Инфраструктура и хостинг» (`04-infrastructure.md`)

### Что изображено

5 «облачных контейнеров»:
- **QazCloud VDC Koshy** — 4 группы прод-серверов: ABAI (CentOS 7 ⚠️), единая платформа УТО+ИСОТ+Work, Team, Электронный архив.
- **GPU-кластер ABAI** — 5×IBM POWER 9 8335-GTH + NVIDIA Tesla V100, ~895 ГБ диск, 635 ГБ ОЗУ, архитектура ppc64le.
- **QazCloud VDC Aqqol** — основная масса корпоративных систем (САПФИР, АСДЦ, СДД, ИСУП, Интранет, BoardMaps, Procu/Price, АИСЭМ, Compliance, БДА, Санау, сайт КМГ).
- **On-Prem** — Bitrix ANPZ (anpz.kz), ИС УТО ЭМГ, портал АО «КазТрансОйл», мобильное приложение КТО (proxmox-Pavlodar).
- **Внешний cloud** — публичные Bitrix-сайты kmg-kumkol.kz и kpi.kz.

Плюс блок «Общие сервисы»: AD, SMTP, SIEM, антивирус, Nessus, VPN/Checkpoint VPN, и явный негативный блок «MFA нет, WAF — только БДА, Vault — только BoardMaps, API Gateway нет».

### Что эта схема позволяет увидеть

- **Концентрация рисков на VDC Aqqol** — там 12 из 20 прод-систем; одна авария VDC = одновременный отказ САПФИР, АСДЦ, СДД, ИСУП, Интранета, BoardMaps.
- **АСДЦ — настоящая «капсула времени»**: ODB-DC и OLAP-DC на Win Server 2012 R2 (EOL октябрь 2023), web-ast-dc на Ubuntu 14 (EOL апрель 2019). Это означает отсутствие патчей безопасности 2,5–7 лет.
- **CentOS 7 в ABAI** — EOL 30.06.2024. С 1 июля 2024 нет даже коммерческих расширенных патчей от Red Hat. ИС наивысшей категории C/I/A 4/4/4 работает на ОС без обновлений.
- **Внешние админы**: ИСУП и Интранет администрировались ТОО «KMG DIGITAL» — учётные записи в AD отключены, но **остались в группе Remote Desktop Users**. Это классический misconfiguration.

## 7.5. Описание схемы 05 — «Данные и хранилища» (`05-data.md`)

### Что изображено

8 кластеров технологий:
1. **PostgreSQL** — основная СУБД ДПППС, 6 разных инсталляций (abaiprot, Patroni HA СДД, PG 17 Procu, ИСОТ+Work+АИСЭМ, ЭА, БДА/Бюро PG 11).
2. **MS SQL Server** — 5 систем (АСДЦ на 2014, ИСУП, Интранет Always On HA, BoardMaps, САПФИР вместе с PG).
3. **MySQL / MariaDB** — все Bitrix-инсталляции + SCADA-буферы ABAI.
4. **NoSQL** — только MongoDB в Directum Insarco (САПФИР).
5. **BigData / OLAP** — стек внутри ABAI: Druid, Spark 3.3.0, Kafka 3.2.1, Hadoop/HDFS.
6. **BI** — Power BI (ИСУП), Qlik/QlikSense (Procu/Price; источник АСДЦ), OLAP-DC АСДЦ (Win Server 2012 R2).
7. **Объектные хранилища** — MinIO (УТО, Procu/Price), SeaweedFS S3 (СДД).
8. **Кэш + Очереди** — Redis в 6 системах, Memcached (только сайт КМКЛ), SP Distributed Cache (Интранет/ИСУП); RabbitMQ в 6 системах, Kafka в ABAI + Бюро пропусков.

Плюс таблицы:
- Сводная таблица СУБД;
- Категория информации и оценки C/I/A;
- Контуры доступа (AD/SSO, JWT, OAuth2, OWIN Cookie, VPN, MFA, WAF, Vault, API Gateway, ЭЦП).

### Что эта схема позволяет увидеть

- **PostgreSQL — де-факто корпоративный стандарт** для собственной разработки ДПППС. Это упрощает миграцию между системами и переиспользование DBA-компетенций.
- **MS SQL Server остаётся «принудительно» там, где Microsoft-стек** (SharePoint, MS Project Server, Directum платформа), плюс legacy АСДЦ на MS SQL 2014.
- **Только одна система использует Vault** (BoardMaps — внешний вендор) и **только одна — WAF** (БДА). Остальные хранят секреты в env / appsettings.
- **C/I/A 4/4/4** только у ABAI; у АСДЦ 3/3/3; у остальных — 2/2/2 или вообще не заполнено (значительная часть систем). При этом в реестре ОИБ должно стоять для всех.
